miniQMT 迁移

把原 miniQMT / xtquant 策略迁移到大 QMT 桥接链路时，先迁移实时交易、查询和行情能力，不把回测数据读取放入主链路。

xtquant 兼容 大 QMT 桥接 迁移评估

适合迁移的能力

  • 买入、卖出、撤单。
  • 委托、成交、持仓、资金查询。
  • 行情快照、K 线、订阅和全推行情。
  • 外部 Python 多进程访问同一个资金账号。
  • 多账号、多 QMT、普通账户和信用账户分开绑定。

不建议直接迁移的能力

cfquant 定位是把大 QMT 的实时交易、查询、行情和回调能力转接给外部系统，不替代本地数据库或回测数据引擎。

  • 大批量历史数据回测读取。
  • 高频反复读取本地文件型行情数据。
  • miniQMT 客户端连接管理、行情服务器管理、本地数据目录控制。

迁移后的请求链路

外部策略进程
  -> cfquant Python SDK / HTTP API / Web 控制台
  -> cfquant Web 统一路由
  -> PipeHub 或 LTtx
  -> QMT 入口脚本
  -> 大 QMT 交易、查询、行情能力

核心差异

项目miniQMT 常见方式cfquant 大 QMT 方式
运行位置外部程序连接 miniQMT 客户端大 QMT 内运行桥接脚本，外部程序请求本地 cfquant 服务
账号识别常用 session 区分连接使用 Web 绑定生成的账号配置和桥接通道
多进程访问各自创建 trader/session统一请求本机服务，再由 PipeHub/LTtx 路由
低延迟交易依赖 miniQMT 和券商环境通用模式可用 ctypes，高级模式可接极速交易端

迁移步骤

  1. 列出当前策略真实用到的 xtquant 接口。
  2. 先部署通用模式，验证资金、持仓、委托、成交等只读能力。
  3. 再验证下单、撤单和交易回调。
  4. 需要更低交易延迟时，切到高级模式并部署双 QMT 入口。
  5. 把回测或批量历史数据读取从桥接链路中拆出去，改为本地数据库或文件处理。
