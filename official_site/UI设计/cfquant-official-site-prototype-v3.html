结果 0 个模块
模块路径主要职责常见定位点
外部 API 总入口cfquant/__init__.py暴露 xtdata、xttrader、xttype、configure 等兼容入口。迁移 miniQMT 调用习惯时先看这里。
交易兼容层cfquant/xttrader.py负责 XtQuantTrader、账号订阅、下单、撤单、交易查询和交易回调派发。交易接口或回调签名不一致时定位。
行情兼容层cfquant/xtdata.py负责行情查询、行情订阅、数据下载和条件兼容接口。on_tick、数据下载进度和行情缺口。
配置、频道与协议config.py / channels.py / protocol.py维护 transport、pipe name、bridge_id，并统一封装 request、response 和 event。频道名、序列化和 bridge 对不上。
RPC 客户端选择cfquant/client.py根据 transport=auto、ctypes、lttx、web_lttx 创建对应客户端。判断请求为什么走 Web、PipeHub 或 LTtx。
Web 服务cfquant_web_server.py维护 Web 控制台、账号配置、统一路由、运行时注册、callback 监听和 WebSocket 推送。多账号、fallback、控制台状态异常。
PipeHub 核心cfquant/pipe_hub.py作为外部 Python、Web 和 QMT Pipe 桥之间的 named pipe 消息代理。ctypes、lite 和通用模式的连接问题。
LTtx 服务LTtx/tx/LTtx_server.py提供本机 socket 发布订阅，用于 Web route、运行时发现和高级模式直连。auto 发现、Web route 和高级模式请求。
通用模式入口qmt_scripts/CFQUANT_CTYPE_ALL_LOWLAT.py单个 QMT 策略内启动 normal 和 trade 两个 Pipe 通道。快速部署和多数常规使用。
极致模式入口qmt_scripts/CFQUANT_LITE.py自包含入口，适配无法正常导入 cfquant 包的 QMT 环境。白名单限制严格的本地终端。
高级模式入口CFQUANT.py + CFQUANT_TRADE_LOWLAT.py普通桥负责查询、行情和账号级回调，交易桥入口只处理交易请求。低延迟交易和回调职责拆分。
普通桥cfquant/normal_bridge.py处理普通请求队列、行情订阅转发、callback event 通道和 QMT 原始交易回调发布。账号级广播回调的源头。
交易桥cfquant/tx_trade_bridge.py分发 passorder、cancel、交易查询、账号订阅和请求级事件。同步响应只回到发起 client_id。
Pipe 桥cfquant/pipe_bridge.py把 NormalQmtBridge 和 TxTradeBridge 包装成通过 PipeHub 通信的 QMT 侧桥。QMT 侧与 PipeHub 的边界。
