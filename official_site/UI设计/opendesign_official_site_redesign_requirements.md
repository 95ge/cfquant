# cfquant.org 官网 UI 重设计需求

更新时间：2026-08-30

本文档用于给 Opendesign / OpenDesign 生成 cfquant.org 官网新版界面方案。设计目标不是做一个泛营销落地页，而是把 cfquant 的产品定位、下载更新、部署学习、社区讨论和问题反馈组织成一个可信、清晰、可操作的官网体验。

## 1. 项目定位

cfquant 是面向大 QMT 的本地转接层，核心目标是把大 QMT 已有的行情、查询、交易、回调能力整理成更轻、更稳定、外部 Python 程序更容易调用的 miniQMT 使用层。

官网的角色：

- 让新用户快速理解：cfquant 不是重做交易终端，而是把大 QMT 能力转成 miniQMT 形态来用。
- 让用户快速下载最新项目包，并理解版本、更新日志、校验信息和 GitHub 备用入口。
- 让用户找到部署、升级、接口迁移、常见问题和社区讨论入口。
- 让用户提交反馈、查看公开处理进度，并在登录后跟踪自己的反馈和通知。

建议首页主表达：

- 产品名：cfquant
- 主标语：把大 QMT 转成 miniQMT 形态来使用
- 辅助说明：面向 QMT 用户和 Python 量化开发者的本地桥接层，统一封装行情、交易、回调、账号路由和更新反馈。

## 2. 设计目标

1. 首屏 3 秒内说明 cfquant 是什么、解决什么问题、下一步该点哪里。
2. 突出“下载最新版本”和“查看部署文档”，把论坛和反馈作为支持闭环。
3. 视觉上体现金融工程工具的专业可信感，避免加密货币风、纯炫技科技风和过度营销感。
4. 信息密度适中，适合开发者和交易系统用户快速扫描版本、模式、部署路径和问题状态。
5. 保留现有官网的功能入口，不破坏当前业务结构：项目、论坛、下载、反馈、用户中心、登录注册、主题切换。
6. 支持桌面端、平板和手机端，移动端优先保证下载、反馈和论坛阅读可用。

## 3. 目标用户

- 新用户：正在从 miniQMT / xtquant 接入方式迁移到大 QMT，希望先看懂方案和部署步骤。
- 已有 QMT 用户：需要快速下载、升级、回滚、查看版本日志和校验包完整性。
- Python 量化开发者：关注接口兼容性、调用方式、多账号、低延迟和回调能力。
- 排障用户：遇到 QMT 部署、行情订阅、交易请求、Socket / PipeHub 桥接、更新安装问题，需要论坛或反馈支持。
- 维护者 / 管理员：需要官网界面能承载公告、版本包、公开反馈和社区内容。

- 文档：部署指南、外部 Python 接入、miniQMT 迁移、运维更新、接口兼容说明。若短期没有独立文档页，可先链接到 GitHub / README / docs。
- 论坛：问题讨论、搜索、分类、帖子详情

顶部右侧：

- 明暗主题切换

## 6. 首页 / 项目页需求

### 6.1 首屏

首屏必须出现：

- cfquant 品牌名和简洁标识。
- 主标语：把大 QMT 转成 miniQMT 形态来使用。
- 一段说明：cfquant 把依赖本地终端、接口分散的大 QMT 能力，整理为外部程序更容易调用的 miniQMT 使用层。
- 主要 CTA：下载最新版本。
- 次要 CTA：查看部署文档、提交反馈或进入论坛。
- 最新版本摘要：核心版本、Web 版本、更新时间、下载次数，能从下载接口数据中映射。
- 产品视觉：使用真实或半真实的产品界面、运行链路图、控制台截图，不使用纯抽象渐变图形作为主视觉。

首屏视觉建议：

- 右侧或背景主体展示“大 QMT -> cfquant -> miniQMT / 外部 Python”的运行链路。
- 可结合现有素材：
  - `official_site/frontend/assets/product-console.png`
  - `official_site/frontend/assets/qmt-console-clean.png`
- 如果重新生成视觉资产，应体现实际产品界面、运行状态、账号路由、行情/交易/回调模块，而不是纯装饰图。

### 6.2 首页内容模块

建议模块顺序：

1. 项目定位：不是重做交易终端，而是把大 QMT 变轻。
2. 核心能力：miniQMT 无缝切换、大 QMT 功能转接、多账号运行、低延迟链路。
3. 模式对比：通用模式、极致模式、高级模式。
4. 运行路径：安装项目包 -> 启动 Web 控制台 -> 配置账号/QMT 路径 -> 加载 QMT 入口脚本 -> 外部 Python 调用。
5. 使用场景：策略程序接入、运行监控排查、下载与反馈闭环。
6. 最新版本与下载入口：显示当前可下载包和 GitHub 备用入口。
7. 社区支持：热门讨论、公开反馈、提交问题入口。

### 6.3 模式对比内容

通用模式：

- 一个 QMT 加载 `CFQUANT_CTYPE_ALL_LOWLAT.py`
- Web / 外部 Python -> PipeHub -> ctypes 单文件桥 -> QMT
- 适合快速部署、单账号验证、多数常规使用

极致模式：

- 一个 QMT 加载 `CFQUANT_LITE.py`
- QMT 侧入口完全自包含，不需要导入 `cfquant` 核心包
- 适合国泰君安君弘智 QMT 等白名单限制严格环境

高级模式：

- 两个 QMT：普通 QMT 加载 `CFQUANT.py`，极速交易端 QMT 加载 `CFQUANT_TRADE_LOWLAT.py`
- 适合追求更低下单、撤单延迟的场景

模式对比应使用表格或对比卡片，但信息不要太长；详细内容可引导到文档。

## 7. 下载页需求

下载页必须突出“最新版本”。

最新版本卡片字段：

- 渠道：如 project / stable / fallback
- 标题
- 核心版本：`core_version` 或 `version`
- Web 版本：`web_version`
- 文件大小：`file_size`
- 更新时间：`updated_at`
- 下载次数：`download_count`
- SHA256：`sha256`
- 更新日志：`changelog.items`
- 主按钮：下载最新项目
- 次按钮：GitHub 或外部链接

历史下载列表字段：

- 标题
- 渠道
- 版本
- 大小
- 下载次数
- 说明
- SHA256 简略显示，悬停或复制时可查看完整值
- 下载按钮
- 外部链接按钮

状态要求：

- 没有官网镜像包时，显示“官网镜像包待登记”，并提供 GitHub 备用入口。
- 下载失败或接口不可用时，给出明确错误状态，不让用户误以为按钮无响应。
- SHA256 应支持复制或至少清晰展示，帮助用户校验文件完整性。

## 8. 论坛页需求

论坛列表：

- 页面标题：cfquant 讨论区。
- 描述：集中跟踪 QMT 部署、行情订阅、交易请求、Socket 桥接和更新安装问题。
- 分类 tabs：全部 + 后端返回分类。
- 搜索框：支持关键词、错误信息、接口名。
- 发布问题按钮：未登录时引导注册 / 登录。
- 帖子卡片字段：标题、摘要、分类、标签、状态、作者头像/昵称、回复数、浏览数、最后活跃时间。
- 状态：开放、已锁定。
- 空状态：暂无匹配讨论，提示换关键词或发起新问题。

帖子详情：

- 返回论坛按钮。
- 标题、分类、作者、创建时间、浏览数、回复数、标签、锁定状态。
- 正文阅读区域。
- 回复列表支持主回复和子回复层级。
- 回复支持图片附件缩略图和点击预览。
- 未登录时显示“登录后回复”。
- 帖子锁定时显示“帖子已锁定，暂不能继续回复”。

发布问题表单：

- 分类
- 标签
- 标题
- 问题描述
- 提交 / 取消

## 9. 反馈页需求

反馈页采用工作台式布局，不做营销风。

主结构：

- 左侧或顶部切换：公开反馈、提交反馈、我的反馈。
- 公开反馈默认展示，强调处理透明度。
- 提交完成后回到公开反馈列表。

公开反馈卡片字段：

- 标题
- 编号
- 创建时间
- 状态：待处理、处理中、已关闭
- 反馈人：匿名用户或昵称
- 摘要
- 截图附件
- 处理回复
- 更新时间

提交反馈表单：

- 标题
- 联系邮箱，必须填写有效邮箱，用于接收处理回复
- 问题描述
- 截图附件，最多 4 张，每张不超过 3MB，支持 png / jpg / webp / gif
- 支持 Ctrl+V 粘贴截图的交互提示
- 提交按钮

我的反馈：

- 未登录时显示注册 / 登录引导。
- 已登录后显示用户提交过的反馈、公开状态、处理状态和管理员回复。

图片交互：

- 附件以缩略图展示，点击后在站内弹窗预览。
- 图片加载失败要有占位状态。

## 10. 用户中心需求

未登录状态：

- 显示未登录说明。
- 提供注册 / 登录按钮。

已登录状态：

- 个人摘要：头像、昵称、用户名、手机号、邮箱、注册时间。
- 个人资料表单：昵称、头像选择、头像上传。
- 头像：保留现有内置头像选择，也支持上传 png / jpg / webp / gif，最大 2MB。
- 邮件通知偏好：
  - 反馈有处理回复时发邮件。
  - 帖子或评论有回复时发邮件。
- 密码设置 / 更新。
- 退出登录。
- 通知列表：标题、内容、创建时间、已读/未读、标记已读、全部已读。

用户中心应该更像设置页和通知中心，不需要大面积宣传文案。

## 11. 注册 / 登录弹窗需求

弹窗结构：

- 标题：注册 / 登录。
- tab 切换：注册、登录。
- 关闭按钮。

注册字段：

- 用户名，3-32 位。
- 手机号，必填。
- 邮箱，可选。
- 昵称，可选。
- 密码。
- 确认密码。
- 按钮：注册并登录。

登录字段：

- 用户名 / 手机号 / 邮箱。
- 密码。
- 记住账号。
- 保持登录状态。
- 按钮：登录。

交互要求：

- 密码错误、字段缺失、两次密码不一致等状态要清晰提示。
- 登录成功后弹窗关闭，并刷新右上角用户状态。
- 移动端弹窗不能超出屏幕，表单可滚动。

## 12. 视觉风格要求

整体关键词：

- 专业
- 克制
- 可信
- 工程化
- 清晰可操作
- 面向量化交易和本地工具

避免：

- 夸张的 Web3 / 加密货币视觉。
- 大面积紫蓝渐变、发光球、抽象光效、纯装饰图。
- 过度营销型 hero 和空洞标语。
- 只用一种蓝色拉满全站。
- 圆角过大的卡片和按钮。

颜色：

- 默认浅色主题，支持深色主题。
- 主色可使用稳定的蓝色或青蓝色，但页面要有中性色、状态色和适度层次。
- 状态色建议：成功/已处理为绿色，警告为琥珀色，错误为红色，信息/主操作为蓝色。
- 文本对比度必须满足可读性要求。

排版：

- 中文优先，兼顾代码与版本号阅读。
- 页面正文 14-16px，标题分级明确。
- 版本号、SHA256、接口名、脚本名使用等宽字体或代码样式。
- 不要用随视口宽度变化的字体大小。

布局：

- 桌面端建议最大内容宽度 1180-1280px。
- 首屏应让下一屏内容露出一点，不要做满屏封闭式海报。
- 卡片圆角不超过 8px。
- 不做卡片套卡片。
- 表格、列表、表单、状态标签要稳定，不因内容变化引发布局跳动。

图标：

- 按钮和功能入口建议配图标。
- 常见操作使用熟悉图标：下载、外链、搜索、刷新、上传、关闭、返回、复制、登录、通知。
- 不用纯文字伪装图标。

## 13. 响应式与可访问性

断点建议：

- Desktop：1440px
- Laptop：1200px
- Tablet：768-1024px
- Mobile：375-430px

可访问性要求：

- 所有按钮、表单、tab、菜单都要有明显 hover / focus / active / disabled 状态。
- 键盘可操作：导航、论坛帖子卡片、弹窗关闭、图片预览关闭。
- 弹窗打开后焦点应停留在弹窗内。
- 图片必须有 alt 文案。
- 错误提示不能只依赖颜色。
- 支持 `prefers-reduced-motion`，重要功能不依赖动画才能理解。

移动端要求：

- 顶部导航不能挤压品牌和登录按钮。
- 表单输入和按钮高度适合触控。
- 下载卡、反馈卡、帖子卡在窄屏下单列显示。
- SHA256 等长文本必须换行或折叠，不能撑破屏幕。

## 15. 内容与文案要求

文案语气：

- 直接、准确、工程化。
- 不夸大收益，不承诺交易收益或固定延迟。
- 清楚区分“通用模式”“极致模式”“高级模式”的适用场景。
- 对下载、更新、截图反馈、邮件通知等操作给出必要说明。

推荐保留文案：

- 把大 QMT 转成 miniQMT 形态来使用。
- 不是重做一个交易终端，而是把大 QMT 变轻。
- 官网镜像包优先，GitHub 不可访问时仍可下载和更新。

- 延迟测试只能表述为实测环境下的参考数据。
