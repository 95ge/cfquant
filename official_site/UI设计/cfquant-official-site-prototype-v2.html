核心能力

不是重做交易终端，而是把大 QMT 变轻。

首页的信息顺序从“理解产品”到“选择模式”再到“下载和排障”，降低开发者首次访问的判断成本。

miniQMT 形态迁移

把大 QMT 的本地能力整理成外部程序更熟悉的调用层，降低迁移和部署理解成本。

大 QMT 功能转接

围绕行情、查询、交易和回调做统一封装，让 Web 控制台与 Python 程序走同一条链路。

多账号运行

把账号路径、入口脚本、运行状态和反馈入口放在同一套信息结构里，便于维护者排查。

下载与反馈闭环

官网镜像、GitHub 备用入口、论坛讨论和公开反馈状态共存，减少问题在私聊中丢失。

模式对比

三种接入模式，按环境限制和延迟目标选择。

模式QMT 侧脚本链路适用场景
通用模式CFQUANT_CTYPE_ALL_LOWLAT.pyWeb / 外部 Python -> PipeHub -> ctypes 单文件桥 -> QMT快速部署、单账号验证、多数常规使用。
极致模式CFQUANT_LITE.pyQMT 侧入口自包含，不导入 cfquant 核心包。白名单限制严格的 QMT 环境。
高级模式CFQUANT.py + CFQUANT_TRADE_LOWLAT.py普通 QMT 与极速交易端 QMT 分工。需要更低下单、撤单延迟的实测环境。
