                      单账号 + 通用模式 + 填写 QMT 核心目录。QMT 核心目录通常是安装目录下的 bin.x64，保存后系统会写入通用端身份配置。

                          按步骤完成账号配置、QMT 部署、通道检测和数据验证。
                        

                        
                      

                      

                        
                        
                        
                        
                        
                      


                      

                        

                          先读懂整体架构，再开始部署
                          这个页面会在首次部署时自动弹出，也可以随时从“新手引导”重新打开。请先确认通用模式和高级模式的通信链路、QMT 数量和适用场景，再继续保存账号。
                        

                        

                          

                            推荐新用户从通用模式开始
                            一个 QMT 加载一个 ctypes 通用端文件，外部程序和网页都通过本机 PipeHub 转发请求，部署步骤少，适合先把资金、持仓、行情和下单链路跑通。
                          

                          

                            高级模式用于追求交易端极限延迟
                            需要 LTtx 服务和两个 QMT：普通 QMT 承担查询/行情，极速交易端 QMT 承担下单/撤单。高级模式部署复杂，但交易端延迟更低。
                          

                        

                        

                          
                          请仔细阅读：高级模式不是在同一个 QMT 里加载两个高级脚本，而是打开两个 QMT，分别承载普通查询桥和极速交易桥。
                        

                        

                          

                            

                              通用模式：ctypes + PipeHub
                              默认推荐，单账号/单 QMT 先用它

                            通用模式怎么通信
                            外部 Python 的 cfquant 默认连本机 PipeHub，PipeHub 再把请求转发到 QMT 里的 ctypes 通用桥。只要 Web 服务或独立 PipeHub 在线，通常不需要 LTtx。

                            外部请求经 LTtx 分发到两个 QMT：普通 QMT 负责查询/行情，极速交易端负责下单/撤单。两个高级入口不要放在同一个 QMT 里同时运行。
                          

                          

                            如何选择
                            不确定时选通用模式。等资金、持仓、行情、委托和撤单都验证成功，再为低延迟交易切高级模式；高级模式异常时系统可回退到通用模式。

看到问题时先查这三处

                    

                      PipeHub
                      状态里是否出现 cfquant.normal.request 和 cfquant.trade.request，多 QMT 时会出现带 bridge_id 的独立频道。
                      QMT 日志
                      通用端应看到 ctypes / Pipe 相关日志；如果持续出现 LTtx 连接失败，通常是旧高级脚本仍在运行。
                      绑定状态
                      账号的首选模式、实际模式、QMT 目录是否符合当前部署。
                    

                  

                


                

                  

                    
项目介绍

                    
cfquant 是一个运行在本机的 QMT 交易桥接控制台。它把网页控制台、外部 Python 程序和 QMT 策略脚本连接起来，让外部程序可以通过统一接口完成资金查询、持仓查询、委托查询、下单、撤单和实时回调接收。

                    

                      首次启动必须完成初始化
                      网页首次打开会要求输入默认账号和运行模式。QMT 核心目录建议填写，通常是 QMT 安装目录下的 bin.x64；留空不影响连接，但会导致自动更新和多 QMT 部署辅助不可用。默认是单账号；增加第二个账号时，继续在“绑定”页面添加账号配置即可。
                    

                  

                      先选择通信模式
                      通用模式只需要加载 CFQUANT_CTYPE_ALL_LOWLAT.py 一个 QMT 文件，行情、查询、下单、撤单和回调统一通过 ctypes 单文件桥接入。高级模式需要两个 QMT 终端：普通 QMT 加载 CFQUANT.py，极速交易端 QMT 加载 CFQUANT_TRADE_LOWLAT.py。不要在同一个 QMT 里同时运行高级模式两个入口。
                    

                    
系统里最重要的概念是账号配置。用户只需要关心资金账号、QMT 核心目录、首选模式和共享行情源；内部通道 ID 由服务端自动分配，用于在多账号、多 QMT 同时运行时把请求转发到正确终端。

快速开始

                    
README 会先帮助你启动本地服务；网页首次打开时必须先完成初始化。真正接入 QMT 时，按每个账号配置的模式加载对应入口。通用模式只加载一个 ctypes 文件和核心包；高级模式需要两个 QMT，普通 QMT 加载普通桥，极速交易端 QMT 加载极速交易桥。

                    
    
                      
  1. 启动 Web：双击 cfquant\start_cfquant.bat，打开 http://127.0.0.1:8765/。
    2. 
                      
  2. 完成初始化：输入默认账号，选择通用模式或高级模式；QMT 核心目录建议填写为 bin.x64，留空会使自动更新不可用。
    3. 
                      
  3. 部署到 QMT：按左侧“部署到 QMT”章节，把核心包放到 bin.x64，把桥接脚本放到相邻的 python 目录。
    4. 
                      
  4. 加载桥接脚本：通用模式加载 CFQUANT_CTYPE_ALL_LOWLAT.py；高级模式打开两个 QMT，普通 QMT 加载 CFQUANT.py，极速交易端 QMT 加载 CFQUANT_TRADE_LOWLAT.py。
    5. 
                      
  5. 配置多账号：进入“绑定”页面继续添加账号，为每个账号填写 QMT 目录和模式；可指定一个账号作为共享行情数据源。
    6. 
                      
  6. 验证连接：刷新状态和资产持仓；高级模式不可用时，账号状态应显示已回退到通用模式。
    7.

                      状态

Python 接入前提

                    
外部 Python 程序可以把 cfquant 当作 xtquant 兼容层使用。使用前需要先启动本地 start_cfquant.bat，并按当前模式加载 QMT 入口：通用模式加载 CFQUANT_CTYPE_ALL_LOWLAT.py；高级模式打开两个 QMT，分别加载 CFQUANT.py 和 CFQUANT_TRADE_LOWLAT.py。Web 控制台里也要先完成资金账号配置。

                    

                      cfquant 不是直接连接柜台的独立交易客户端
                      外部 Python 请求会先连接本机 Web 通信层，再由当前模式的 QMT 桥接脚本调用 QMT 原生能力。因此 QMT 必须登录账号并保持对应入口脚本运行。
                    

                  


                  

                    
安装方式

                    
cfquant 暂未发布到 PyPI，因此暂不支持 pip install cfquant。当前只支持从本地源码目录安装。

                    
cd D:\cfquant
pip install -e .

# 或安装当前源码版本
pip install .

                    
如果不想使用 pip，也可以把源码里的 cfquant\ 和 LTtx\ 两个目录复制到你的 Python 项目根目录，或复制到当前 Python 环境的 site-packages 目录。

                  


                  

                    
替代 xtquant 导入

                    
原来使用原生 xtquant 的代码：

                    
from xtquant import xtdata
from xtquant.xttrader import XtQuantTrader
from xtquant.xttype import StockAccount

                    
可以改成：

                    
from cfquant import xtdata
from cfquant.xttrader import XtQuantTrader
from cfquant.xttype import StockAccount

                    
如果原项目里大量使用 import xtquant，可以用别名方式减少改动：

                    
import cfquant as xtquant

data = xtquant.xtdata.get_full_tick(["000001.SZ"])

                  


                  

                    
连接配置

                    
默认使用通用模式的 ctypes 单文件桥。单 QMT 场景通常不需要手动调用 configure；只要 start_cfquant.bat 已启动、QMT 侧已加载当前模式对应的桥接脚本，xtdata 就可以像原生 xtquant.xtdata 一样直接使用。

                    
只有需要修改 LTtx 地址、端口、token、超时时间，或给没有账号映射的请求指定默认内部通道时，才需要调用 configure：

                    
from cfquant import configure

configure(
    host="127.0.0.1",
    port=2049,
    token="LTtx",
    timeout=15,
)

                    
也可以通过环境变量配置：

                    
CFQUANT_LTTX_HOST=127.0.0.1
CFQUANT_LTTX_PORT=2049
CFQUANT_LTTX_TOKEN=LTtx
CFQUANT_TIMEOUT=15

部署到 QMT

                    

                      按当前模式部署 QMT
                      本地服务需要运行 start_cfquant.bat。通用模式加载 CFQUANT_CTYPE_ALL_LOWLAT.py 一个文件即可；高级模式需要两个 QMT，普通 QMT 运行 CFQUANT.py，极速交易端 QMT 运行 CFQUANT_TRADE_LOWLAT.py，缺少任一桥时高级模式不会启用。
                    

                    
QMT 策略入口脚本通常放在安装目录下的 python 文件夹，核心包放在同级的 bin.x64 文件夹。入口脚本已兼容从相邻的 bin.x64 导入 cfquant。

                    
发布包的外层 cfquant 目录用于启动 Web；其中 cfquant\cfquant\ 是要复制到 QMT 的核心包，cfquant\qmt_scripts\ 是要放进 QMT python 目录并加载运行的入口脚本。

                    
例如 QMT 安装在 D:\国金证券QMT交易端 时，核心目录是 D:\国金证券QMT交易端\bin.x64，入口脚本目录是 D:\国金证券QMT交易端\python。

                  


                  

                    
QMT 文件放置位置

                    

                      

                        
                          

                            项目文件
                            放置位置
                            用途
                          

                        
                        
                          

                            cfquant\cfquant\ 目录
                            复制到 QMT 的 bin.x64\cfquant\
                            两种模式都需要的桥接核心包，包含 ctypes、普通桥、极速交易桥、频道规则和协议解析。
                          

                          

                            cfquant\qmt_scripts\CFQUANT_CTYPE_ALL_LOWLAT.py
                            通用模式复制到 QMT 的 python\ 根目录
                            单文件 ctypes 通用桥，同时注册查询、交易和回调通道；不需要 tx.py。
                          

                          

                            cfquant\qmt_scripts\CFQUANT.py
                            复制到普通 QMT 的 python\ 根目录
                            普通 QMT 桥入口，负责资金、持仓、委托、成交和状态查询。
                          

                          

                            cfquant\qmt_scripts\CFQUANT_TRADE_LOWLAT.py
                            复制到极速交易端 QMT 的 python\ 根目录
                            极速交易桥入口，负责低延迟下单、撤单和交易回调。
                          

                        
                      

                    

                    

                      保持目录层级不变
                      通用模式的目标 QMT 应能看到 bin.x64\cfquant\__init__.py 和 python\CFQUANT_CTYPE_ALL_LOWLAT.py。高级模式的普通 QMT 放 CFQUANT.py，极速交易端 QMT 放 CFQUANT_TRADE_LOWLAT.py；LTtx 客户端已内置在 bin.x64\cfquant\tx.py。
                    

                    

                      目标目录示例
                      如果 QMT 安装在 D:\兴业证券SMT-Q，核心目录通常是 D:\兴业证券SMT-Q\bin.x64；如果安装在 D:\国金证券QMT交易端，核心目录通常是 D:\国金证券QMT交易端\bin.x64。
                    

                  


                  

                    
部署步骤

                    
    
                      
  1. 关闭或停止旧桥接脚本：如果 QMT 里已经加载过旧版 CFQUANT.py 或 CFQUANT_TRADE_LOWLAT.py，先停止旧策略，避免多个旧实例抢同一频道。
    2. 
                      
  2. 复制依赖包：把发布包里的 cfquant\cfquant\ 整个目录复制到目标 QMT 的 bin.x64\cfquant\。
    3. 
                      
  3. 复制入口脚本：通用模式复制 CFQUANT_CTYPE_ALL_LOWLAT.py 到目标 QMT。高级模式把 CFQUANT.py 放到普通 QMT，把 CFQUANT_TRADE_LOWLAT.py 放到另一个极速交易端 QMT；不需要再单独复制 tx.py。
    4. 
                      
  4. 确认本机服务已启动：在发布包外层 cfquant 目录运行 start_cfquant.bat，Web 服务默认启动 PipeHub 和 LTtx 服务端。
    5. 
                      
  5. 在 QMT 加载入口：通用模式在一个 QMT 里加载 CFQUANT_CTYPE_ALL_LOWLAT.py；高级模式在普通 QMT 加载 CFQUANT.py，在另一个极速交易端 QMT 加载 CFQUANT_TRADE_LOWLAT.py。
    6. 
                      
  6. 回到网页验证：进入“绑定”页面保存账号配置，再刷新状态和资产持仓。
    7. 
                    

                  


                  

                    
多 QMT 部署

                    
如果一台机器上同时运行多个 QMT，每个 QMT 都要有自己的 bin.x64\cfquant\ 核心包和 python 桥接入口脚本。网页侧只添加账号配置，不需要手动选择桥接端；填写 QMT 核心目录后，服务端会在对应 bin.x64 写入 cfquant_bridge_config.json，通用端启动时按这个身份注册到独立频道。

                    
# 示例：第二组 QMT 终端使用独立 bridge_id
USER_BRIDGE_ID = "qmt2"

                    
高级模式下，同一账号的普通 QMT 和极速交易端 QMT 应使用同一个 bridge_id；不同账号或不同 QMT 部署组再使用不同 bridge_id。

                  

                


                

                  

                    
通用模式图文部署指南

                    

                      推荐先按通用模式跑通
                      通用模式只需要一个 QMT，在 QMT 中加载 CFQUANT_CTYPE_ALL_LOWLAT.py，行情、查询、下单、撤单和回调都通过 ctypes 单文件桥接入。
                    

                    
先确认本地服务已通过 start_cfquant.bat 启动，并把 cfquant\cfquant\ 核心包复制到目标 QMT 的 bin.x64\cfquant\。然后按下面截图在 QMT 中创建、部署并启动通用模式策略。

                  


                  

                    
一、下载 Python 库

                    
打开 QMT 的“模型研究”或“模型交易”，点击下载 Python 库，让 QMT 准备好 Python 策略运行环境。

                    
                  


                  

                    
二、导入通用模式脚本

                    
在 QMT 里创建对应的 Python 策略，将 CFQUANT_CTYPE_ALL_LOWLAT.py 的代码复制进去。这个脚本是通用模式唯一需要加载的 QMT 入口。

                    
                  


                  

                    
三、部署策略

                    
按截图在 QMT 中部署刚创建的通用模式策略，确保策略文件保存后再进入启动步骤。

                    
                  


                  

                    
四、启动策略

                    
启动通用模式策略后，它会连接本地 PipeHub，并注册普通请求通道、交易请求通道和回调通道。

                    
                  


                  

                    
五、成功示例

                    
成功后，Web 控制台的 PipeHub 状态应能看到 QMT 通道在线。随后在“绑定”页面保存资金账号和 QMT 核心目录，再刷新资产、持仓或行情验证。

                    
                  

                


                

                  

                    
高级模式图文部署指南

                    

                      高级模式必须准备两个 QMT
                      普通 QMT 加载 CFQUANT.py，负责资金、持仓、委托、成交和状态查询；另一个极速交易端 QMT 加载 CFQUANT_TRADE_LOWLAT.py，负责低延迟下单、撤单和交易回调。
                    

                    
高级模式请求通过 LTtx 双桥转发。两个 QMT 都要复制完整 cfquant\cfquant\ 核心包到各自的 bin.x64\cfquant\，但不再需要手动复制 tx.py，它已经随核心包内置为 cfquant.tx。

                  


                  

                    
一、下载 Python 库

                    
分别在普通 QMT 和极速交易端 QMT 中确认 Python 库已下载，保证两个终端都能运行 Python 策略。

                    
                  


                  

                    
二、创建两个 Python 策略

                    
在普通 QMT 中创建策略并导入 CFQUANT.py；在极速交易端 QMT 中创建策略并导入 CFQUANT_TRADE_LOWLAT.py。两个高级入口不要放在同一个 QMT 里同时运行。

                    
                  


                  

                    
三、启动本地服务

                    
在本项目目录运行 start_cfquant.bat，启动 LTtx 服务和 Web 控制台。高级模式下，网页会检查普通 QMT 桥和极速交易桥是否都在线。

                    
                  


                  

                    
四、确认两个桥接策略在线

                    
分别启动普通 QMT 的 CFQUANT.py 和极速交易端 QMT 的 CFQUANT_TRADE_LOWLAT.py。两个桥都在线后，高级模式才会被启用。

                    
                  


                  

                    
五、网页端绑定高级模式账号

                    
打开 http://127.0.0.1:8765/，在“绑定”页面添加资金账号，模式选择高级模式，并填写对应 QMT 核心目录。保存后刷新状态、资产和持仓进行验证。

多账号通道

                    
内部通道 ID 是 Web Server 识别 QMT 终端的实现字段。普通用户不需要在网页里选择它；单 QMT、单账号默认使用 default，继续添加账号时服务端会按账号配置自动路由。

                    
如果同时运行多个 QMT，例如一个负责实盘账号、一个负责测试账号，建议在账号配置中填写各自 QMT 核心目录。系统会按目录复用或分配内部通道，并把通用端身份写入各自目录下的 cfquant_bridge_config.json。

                    
# 示例：第二个 QMT 终端使用 qmt2
USER_BRIDGE_ID = "qmt2"

账号绑定

                    
账号绑定是一个完整的运行配置。每个账号保存自己的 QMT 核心目录、首选模式、共享行情源和启用状态；网页和外部程序携带账号后，服务端会自动决定内部通道和实际路由。

                    
    
                      
  1. 进入“绑定”页面，在“账号配置”里填写资金账号。
    2. 
                      
  2. 填写 QMT 核心目录并选择通用模式或高级模式；目录可留空，但自动更新不可用。
    3. 
                      
  3. 在“绑定状态”里刷新状态，确认当前账号实际模式在线。
    4. 
                      
  4. 点击验证按钮，检查资金和持仓是否来自预期账号。
    5. 
                    

                  


                  

                    
绑定规则

                    

                      高级模式不可用时自动回退通用模式
                      账号首选高级模式时，系统优先使用 LTtx；如果 LTtx、普通桥或极速交易桥不可用，该账号的查询、行情和交易请求会自动切换到 ctypes 通用桥。高级模式恢复后，后续请求重新优先使用高级模式。
                    

                    
默认是单账号和单数据源。多账号时，每个账号可以使用不同 QMT 安装目录和不同模式；建议指定一个稳定账号作为共享行情数据源，系统会避免重复订阅。数据源账号掉线或请求失败时，服务端会尝试其他已启用账号作为备用数据源。

                  

                


                

                  

                    
交易与回调

                    
交易页把下单、批量下单、撤单、持仓、委托和成交放在同一个工作区。通用模式由 ctypes 单桥自动路由；高级模式下可以分别选择普通 QMT 或极速交易端。

                    

                      

                        
                          

                            操作
                            关键点
                          

                        
                        
                          

                            提交委托
                            填写代码、价格、数量，确认文本必须与页面提示完全一致，避免误操作。
                          

                          

                            批量买入
                            每行一笔委托，格式为 代码,价格,数量，确认文本使用 BATCH 数量。
                          

                          

                            撤单
                            实时委托表会标记可撤委托，可以选择后批量撤单，也可以双击可撤行触发撤单确认。
                          

                          

                            回调
                            委托、成交、下单错误、撤单错误会进入“回调”页，也可以通过 WebSocket 推给外部程序。
                          

                        
                      

                    

                  


                  

                    
实盘操作建议

                    
实盘前先用小数量验证账号、价格和撤单链路。确认回调能返回后，再把外部程序接入自动交易流程。

                    
如果委托提交后页面没有立即变化，先看“回调”页和“日志”，再刷新“委托”。柜台状态、QMT 本地缓存和网络延迟都可能造成短暂不同步。

为什么交易时间更快

                    
    
                      
  • 非交易时间或午间休市时，行情源、QMT 本地缓存、柜台连接状态和脚本回调节奏可能进入低活跃或重置状态，首次请求更容易变慢或超时。
    • 
                      
  • 交易时间内行情和交易链路持续活跃，连接更热，QMT 返回行情快照和交易查询通常更稳定。
    • 
                      
  • 本次非交易时间数据还叠加了 ctypes 早期版本问题；后续在交易时间修复后，ping/status 降到约 40ms，交易查询恢复到约 173-176ms。
    • 
                      
  • 极速交易端适合低延迟下单和交易查询；ctypes 通用版部署更简单，但当前交易查询为保证单文件稳定性，会走转发路径，所以查询延迟高于极速交易端。

排查问题

                    
排查时先判断是哪一层断了：网页是否能访问，本地服务是否启动，LTtx 是否在线，QMT 脚本是否在线，账号配置是否正确。

                    

                      

                        
                          

                            现象
                            优先检查
                            处理方式
                          

                        
                        
                          

                            网页打不开
                            Web Server 是否启动，端口是否被占用。
                            重新运行启动脚本，检查控制台日志和端口配置。
                          

                          

                            LTtx 离线
                            LTtx 进程是否运行，本地通信端口是否正常。
                            在“首页”或“状态”页点击启动 LTtx，再刷新状态。
                          

                          

                            普通在线、极速离线
                            CFQUANT_TRADE_LOWLAT.py 是否在 QMT 中加载。
                            重新加载极速交易桥，确认 bridge_id 与普通桥一致。
                          

                          

                            查不到账号数据
                            账号配置是否对应正确 QMT，QMT 是否登录该账号。
                            在“绑定”页重新保存账号绑定，并用验证功能检查资金和持仓。
                          

                          

                            下单失败
                            确认文本、交易权限、价格数量、交易通道。
                            查看日志和回调错误，先用小数量再次验证。
