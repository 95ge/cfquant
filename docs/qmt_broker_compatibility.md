# 多券商 QMT 虚拟机与 MAC 适配检查

检查日期：2026-11-11。以下结果来自本机安装的 11 个终端样本，只对应这些实际文件，不作为版本号白名单。

## 结论

10 个 `XtItClient.exe` QMT 样本的两处虚拟机检测入口均可由现有规则唯一识别；已检查的 MAC 采集路径均经过现有代理覆盖的 `utils.dll → GetAdaptersInfo / GetAdaptersAddresses`。这些样本不需要按券商另写固定地址或切换 MAC 注入实现。

目录中还有一个 `XtAmpTradeClient.exe` PB 终端。它的登录模块不同，当前 QMT 启动器不支持，不能将它的运行期检测导出存在解读为整个终端已适配。

**客户端采集 MAC、代理能够处理该采集路径、服务器要求账号绑定 MAC，是三个不同的判断。** 本次没有登录账号，不能据此列出哪些券商或账号必须绑定 MAC；客户端含有采集函数也不代表服务端启用了限制。没有 MAC 绑定要求时，保持 MAC 注入关闭。

## 检查依据与边界

- 逐一解析实际主程序、`User.dll` 和 `utils.dll`，核对 x64 格式、模块导出、异常展开表中的函数边界、完整检测函数特征及 ACPI / SMBIOS 调用；UPX 压缩文件仅解包临时副本。
- 追踪 `utils.dll` 的网卡采集 API 调用，包括链接器导入跳板，避免把导入表里出现某 API 当成实际调用证据。
- 这 10 个 QMT 样本的 `GetIfEntry` 辅助函数读取 `MIB_IFROW.dwOperStatus` 来检查网卡运行状态，没有在该辅助函数中读取或返回物理 MAC，因此保留它的原始行为。
- 对检查时已运行的已识别终端，只通过 Windows 的进程查询和内存读取权限核对入口字节，没有注入、改写、停止或重新启动进程。
- 检查前后主程序及两个目标 DLL 的 SHA-256 一致。没有修改客户端安装文件，没有登录账号、下单或更改服务器绑定。
- 这些结果不覆盖每个券商的所有版本、所有登录模式、其他硬件限制或长期运行；文件识别、内存一致性和服务器接受应分别记录。

## 功能选择

cfquant 绑定界面中的“禁用 QMT 虚拟机检测”和“MAC 注入”是独立开关，默认关闭。只需虚拟机适配时，仅开启前者；需要 MAC 测试时再开启后者，并填写使用者自己账号对应的登记地址。不要按券商名称自动注入 MAC。

独立源码版保持现有参数行为：不带 `--launch` 只检查；`--launch` 启用虚拟机适配；附加 `--mac` 才注入 MAC。

```powershell
# 只检查客户端，不启动
.\.venv\Scripts\python.exe .\qmt_vm_start.py --qmt-dir 'D:\QMT\bin.x64'

# 启动时适配虚拟机检测，保留原始 MAC
.\.venv\Scripts\python.exe .\qmt_vm_start.py --qmt-dir 'D:\QMT\bin.x64' --launch

# 同时注入 MAC；以下地址仅为格式示例
.\.venv\Scripts\python.exe .\qmt_vm_start.py --qmt-dir 'D:\QMT\bin.x64' --mac '02-11-22-33-44-55' --launch
```

QMT 更新后应重新执行检查。检测实现不匹配时需要重新分析，不能通过忽略校验、填写其他版本号或直接换用旧地址来判断兼容。
