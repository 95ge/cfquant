# 运维与更新

本文说明 cfquant 的本地服务启停、日志清理、版本检查和更新策略。

## Level2 适配升级

本次 Level2 升级需要同时更新 SDK、Web 和 QMT 桥代码，包括新增 `cfquant/level2.py`；极致模式需同步所用自包含 LITE 入口。更新后重启 Web，并完整退出重启 QMT 和使用 SDK 的 Python 进程，避免旧模块仍驻留内存。不要仅刷新网页或只重启策略。

功能、模式范围、千档限制及只读验收步骤见 [Level2 行情适配说明](Level2行情适配说明.md)。无需为普通 Level2 配置额外的千档接口；没有权限或行情时不能把空数据判为通过。

## 启停脚本

项目根目录提供以下脚本：

```text
start_cfquant.bat       启动本地服务
stop_cfquant.bat        停止本地服务
restart_cfquant.bat     重启本地服务
```

通常日常运维只需要使用 `restart_cfquant.bat`。重启只会重启 Web 和 PipeHub，并保留 LTtx，避免外部 `cfquant` Python 库的自动发现和通信入口中断。

如果用户双击启动脚本后窗口闪退或网页打不开，优先查看：

```text
log/startup/cfquant_startup.log
log/web/cfquant_web_server.*.stderr.log
```

新版 `start_cfquant.bat` 会在启动后等待 Web 健康接口真正可用。若目标端口已经是 cfquant Web，会直接复用已有实例并打开页面；若端口被其他程序占用，会提示占用进程并要求停止该进程或改用 `CFQUANT_WEB_PORT`。启动失败时窗口会停留，并输出最近的启动日志和错误日志，不再直接闪退。

`start_cfquant.bat`、`restart_cfquant.bat` 和 `stop_cfquant.bat` 是项目保留的英文入口。重启会保留 LTtx，只等待旧 Web 端口释放后再启动；停止表示完整退出，会停止 Web、PipeHub 和 LTtx。停止失败时会保留窗口，方便查看失败原因。

需要把错误完整留在当前窗口时，可以在命令行中运行：

```bat
start_cfquant.bat --foreground
```

或：

```bat
start_cfquant.bat --debug
```

自动化脚本中如果不希望失败时停在 `pause`，可以设置：

```bat
set CFQUANT_START_NO_PAUSE=1
```

也可以分别设置 `CFQUANT_RESTART_NO_PAUSE=1` 或 `CFQUANT_STOP_NO_PAUSE=1` 控制重启、停止脚本。

## 日志目录

### 网页运行日志

首页、交易下单、委托查询、运行状态和回调事件页提供“运行日志”，可按功能和账号范围筛选。默认跟随当前页面和当前账号；回调页只展示回调拉取、实时连接及消息解析等回调记录。查看资产、持仓、委托或成交查询错误时，选择“账号查询”；跨账号排查时选择“全部账号”。

同一账号、通道、原因导致的查询失败会合并成一条，显示涉及项目、累计失败次数、首次和最近时间。次数按失败的查询项目累计，例如一次刷新中资产、持仓均失败，累计为 2 次；反复读取同一份失败缓存不会增加次数。详情保留各项目最近一次错误。

部分项目成功时会显示剩余待恢复项目，全部受影响项目成功后才标记“已恢复”；错误原因变化会单独记录，不能当作恢复。账号查询接口恢复访问与 QMT 查询恢复分别显示，接口可以访问不代表 QMT 通道已连接。回调拉取、实时连接和解析错误也分别跟踪恢复状态。

网页记录仅保存在本次打开的页面中，最多保留 180 条合并后的记录，刷新页面会重置。“清空当前结果”只清除符合当前筛选的网页记录，不影响其他分类、账号和磁盘日志。持续的 `QMT_BRIDGE_NOT_CONNECTED` 仍需检查对应账号的 QMT 策略和连接状态，日志合并不会启动策略或改变交易设置。

### 服务日志文件

本地服务日志统一写入项目根目录 `log/`：

```text
log/
  web/
    cfquant_web_server.runtime.log
    cfquant_web_server.<启动时间>.stdout.log
    cfquant_web_server.<启动时间>.stderr.log
  startup/
    cfquant_startup.log
    cfquant_web_reload.log
  lttx/
    lttx_server.stdout.log
    lttx_server.stderr.log
    YYYY-MM-DD_log.csv
    YYYY-MM-DD.log
  pipe_hub/
    cfquant_pipe_hub.stdout.log
    cfquant_pipe_hub.stderr.log
  qmt_bridge/
    cfquant_qmt_bridge.log
```

默认保留最近 30 天日志。Web 服务后台会定期自动清理，也可以在“设置 - 日志清理”中手动执行。

根目录历史遗留的 `*.log`、`log_data/`、`tx_log/` 也纳入清理和 Git 忽略。QMT `userdata/log` 清理默认关闭，需要用户在网页里显式启用。

## 运行数据目录

本地运行状态和配置数据库统一放入 `runtime/`，不提交到 Git：

```text
runtime/
  config/cfquant_web_config.json
  db/cfquant_web_config.db
  lttx/
  reports/
  media/
  cache/
  status/cfquant_pipe_hub_status.json
  screenshots/
```

旧版本根目录下的 `cfquant_web_config.db` 和 `cfquant_pipe_hub_status.json` 属于历史遗留文件，整理项目时可迁移到上述目录。

常用环境变量：

```text
CFQUANT_LOG_DIR=D:\cfquant\log
CFQUANT_LOG_RETENTION_DAYS=30
CFQUANT_LOG_CLEANUP_INTERVAL_SECONDS=21600
CFQUANT_PIPE_HUB_VERBOSE_EVENTS=0
```

`CFQUANT_PIPE_HUB_VERBOSE_EVENTS=1` 会打开 PipeHub 高频事件日志，只建议排查问题时临时使用。

## 回调监听恢复

Web 服务启动时会读取已保存的账号绑定，恢复对应的回调监听，无需每天重新绑定。PipeHub 尚未启动、连接失败或运行中断开时，后台默认每隔 3 秒检查并尝试恢复连接；LTtx 监听单独重试，不会阻塞 Pipe 回调恢复。

修改绑定后会关闭旧通道的监听，再启动新通道；配置未变时复用正常连接，并触发一次连接检查，避免反复保存或重连产生重复监听。日志中的 `callback pipe client start failed ... will retry` 表示仍在重试，`callback pipe listener ready` 表示监听已建立。

此机制适用于 Web 接收及经 Web 转发的回调，更新代码并重启 Web 服务后生效。连接恢复后接收新回调，不补发断线期间的历史回调；资产和持仓仍通过下述快照补查机制校准。

## 账户缓存刷新

资产和持仓采用按需快照、回调增量更新和低频补查，不再默认启动全账号持续预热：

- 首次访问账户时查询快照；相同账户并发缓存请求会合并，避免重复查询。
- 活跃订阅默认每 5 秒补查一次完整快照，不将每条回调当作完整账户数据。
- 有明确账号、类型、桥接来源且可安全匹配的资产或单条股票持仓回调，会直接更新已有快照；缺失字段不会被填零，其他持仓不会被覆盖。
- 新持仓、无法唯一匹配的持仓以及委托、成交变化会标记相关数据待补查，同类后台补查至少间隔 2 秒。回调线程不执行 QMT 查询。
- 每项缓存订阅在 90 秒无人访问后过期。关闭网页、切到其他账号或离开资金持仓页面后，不会永久保留后台轮询；已发出的查询不会强制中断。
- 首页和交易页可见时，每 15 秒读取一次资金、持仓缓存；这个频率不等于 QMT 查询频率。后台标签页不续订。
- 开启实时刷新时，首页和委托页的委托表、交易页当前选中的委托或成交表，每 2 秒读取服务端共享缓存。回调触发的缓存读取也按页面至少间隔 2 秒，不强制直查 QMT；资金、持仓回调仍可提前读取已更新的缓存。多个页面复用同账号、同路由的后台查询与失败退避。
- 隐藏页面、切到无关功能页或关闭实时刷新后，停止上述自动读取；已有服务端缓存订阅最多继续到 90 秒空闲过期，已经发出的查询不强制中断。重新显示时恢复读取，没有新回调时仍能取得后台最终核对结果。
- 委托、成交查询期间若有新回调，保留已完成的完整快照并保持待核对标志，下一轮仍受限频约束。页面不会用重复或更旧的缓存快照覆盖同一账号已显示的新数据；手动查询和下单、撤单后的即时查询保留。
- 绑定页可见时，每 5 秒自动读取全部绑定的在线状态和当前选择账号的资金、持仓。首次默认显示列表第一个账号，之后保留用户选择；切换账号立即读取数据。后台标签页暂停读取，重新显示时立即更新。通道状态监控默认间隔也为 5 秒，可通过 `CFQUANT_WEB_STATUS_INTERVAL` 覆盖。
- 查询失败时保留最近成功的数据，页面明确标记“刷新失败，数据已过期”及最近完整查询时间；首次查询失败显示暂无数据，不填零。接口返回 `ok=false`、`refresh_ok=false`，有历史数据时同时返回 `has_data=true`、`stale=true` 和 `data_checked_at`，不能将保留的数据当作刷新成功。
- 失败后先间隔 5 秒、15 秒进行两次快速重试，连续失败后改为至少 60 秒探测（配置的正常间隔更长时采用该间隔）；成功后恢复正常频率。回调和页面轮询不会绕过失败退避，同账号在途缓存查询仍合并。停止访问或禁用账号后停止后台重试；手动强制刷新可立即尝试。这些重试仅用于只读账户查询。
- 页面按账号、查询类型及失败时间合并错误提示，同一缓存失败不重复刷屏；新一次失败和恢复成功会分别提示。
- 手动强制刷新、网页下单/撤单后的明确刷新、SDK 直接查询保持原有调用语义；成交和委托回调仍正常分发。

需要部署级覆盖时可设置以下环境变量，重启 Web 服务生效：

```text
CFQUANT_WEB_STATUS_INTERVAL=5
CFQUANT_WEB_ACCOUNT_CACHE_INTERVAL=5
CFQUANT_WEB_ACCOUNT_CACHE_IDLE_SECONDS=90
CFQUANT_WEB_ACCOUNT_CACHE_BACKGROUND_TIMEOUT=5
```

`CFQUANT_WEB_ACCOUNT_CACHE_PREWARM_SECTIONS` 默认留空。显式设置为 `asset,positions` 可恢复所有启用账号的持续预热，预热账号不受页面空闲过期限制。已有部署设置的较短刷新间隔仍会生效。

缓存和页面改动在重启 Web 服务、刷新浏览器后生效。完整的查询耗时诊断还需要更新并重启对应 QMT 策略；Lite 的普通、上海、深圳入口均已同步。旧策略仍可查询，但会标记 `bridge_timing_unavailable`，不会把未知的 QMT 执行时间写成零。

资产、持仓、委托和成交查询结果的 `request_timings` 保留每次尝试的请求编号、连接发送耗时、响应等待耗时，以及 QMT 排队、原生查询和执行耗时。Web 日志 `account_query_timing`、PipeHub 日志的转发与响应记录，以及 QMT 日志 `account_query_start` / `account_query_done` 可按同一请求编号关联；合并执行的请求还提供 `coalesced_request_id`。QMT 日志须在设置中开启，原有日志开关继续生效。

超时只代表客户端未在期限内收到响应，此时 `qmt.available=false`、`reason=no_response`；之后 QMT 若完成，仍可通过请求编号查执行日志。尚未执行就过期的请求会标记 `executed=false`。本次使用模拟 QMT 验证，未验证真实券商终端的超时根因；离线回归见 `cfquant/tests/24_账户缓存按需刷新测试.py`、`cfquant/tests/25_账户缓存页面测试.py` 和 `cfquant/tests/test_account_query_timing.py`。

## 全推订阅范围

`xtdata.subscribe_whole_quote(code_list, callback=...)` 和 Web 全推调试接口不再设置 `SH/SZ` 白名单。可以传入市场列表、证券代码列表或混合列表，包括 `BJ`；cfquant 不额外改写证券代码大小写，实际支持范围由 QMT 版本、行情权限和代码有效性决定。

同一服务实例和行情源下，Web 行情、经 Web 接入的 SDK 全推和算法任务复用上游全推及最新行情缓存；QMT 桥接实例也合并普通、诊断和内部全推订阅。使用者保留独立订阅号和引用，取消某个订阅不会中断其他使用者；最后一个引用释放后才撤销上游订阅。已有活动使用者时固定行情源：Web 全推和延迟诊断自动复用已有来源，SDK 和算法显式指定冲突来源时仍报错。QMT 拒绝订阅时返回错误，不仅以分配本地订阅号表示成功。

接口测试页在订阅后显示实际行情源。页面选择的 `bridge_id` 与后台算法或其他页面已使用的桥接不一致时，不再导致 `shared quotes already use another bridge_id`。尚无共享订阅时仍按请求及行情源配置选择来源。

取得订阅号后需点击“连接推送”。服务端会回收未连接的空闲页面订阅，页面点击连接时会先续用或恢复订阅，避免继续连接过期的 ID。连接失败会显示原因并允许重试；在恢复过程中停止或切换订阅，迟到的订阅也会被释放。

普通全推 `POST /api/quotes/whole/subscribe` 和诊断 `POST /api/diagnostics/quotes/subscribe` 共用以下规则：

| 字段 | 位置 | 说明 |
| --- | --- | --- |
| `resume_subscribe_id` | 可选请求字段 | 连接前携带原订阅 ID 和原市场列表；订阅有效时续用，已回收时重新创建。不能用它修改已有订阅的市场范围。 |
| `subscribe_id` | 响应字段 | 本次实际有效的页面订阅 ID；恢复后可能变化，WebSocket 必须使用返回值。 |
| `already_subscribed` | 响应字段 | `true` 表示续用已有页面订阅，`false` 表示新建。 |
| `bridge_id`、`channel`、`account_id` 等 | 响应字段 | 实际使用的行情源。 |
| `requested_bridge_id` | 响应字段 | 最初请求的桥接。 |
| `source_reused` | 响应字段 | 请求的来源字段与实际共享来源存在差异时为 `true`。 |

取消上述共享订阅时，向对应的 `/api/quotes/unsubscribe` 或 `/api/diagnostics/quotes/unsubscribe` 传入 `subscribe_id` 和 `shared_only: true`。订阅已回收时返回 `result: false, already_released: true`，不会将失效的本地 ID 当作 QMT 原生订阅 ID 转发。页面会自动携带此标记，单股订阅的原有取消方式保留。

这项修复涉及核心共享行情服务和 Web 页面，需要安装包含修复的版本、重启 Web 服务并刷新浏览器；只刷新旧版服务的页面不会生效。

共享订阅的续租、恢复、范围变更和慢消费者快照处理见 [算法交易与共享全推行情](algorithm_trading.md)。这套机制减少重复订阅，但不保证逐笔行情不丢失，也不能替代实际全推吞吐验证。账号回调续订超时与交易会话隔离的处理见 [订阅恢复与行情拥塞隔离](subscription_recovery.md)。

完整项目更新会自动同步核心包和绑定模式对应的 QMT 入口到各 QMT 目录，重启 Web 后再重启对应 QMT 策略。本次回归使用模拟 QMT，未验证券商终端的北交所行情权限与实时报价。

## QMT 日志设置

Web“设置 - QMT 日志”可以控制 QMT 侧桥接日志：

- 日志显示默认开启；
- 语言默认中文，也可以切换为 English；
- 保存后会向在线的普通桥和交易桥广播配置；
- 账号绑定写入的 `cfquant_bridge_config.json` 会保存日志语言和日志开关，QMT 入口脚本重启后继续生效。

## 版本检查

Web 左上角会显示当前版本号。鼠标悬停后可以查看：

- 当前本地版本；
- 本地更新日志；
- 远端是否存在新版本；
- 新版本更新日志；
- 版本检查失败原因。

内网或无法访问 GitHub 时，版本探测失败只会在页面顶部提示，不影响交易、行情、账号路由和本地功能。

## 更新策略

Web“设置 - 更新管理”中分为两类更新。

Web 项目更新：

- 可从 GitHub 拉取项目 zip；
- 也可以上传本地 zip；
- 更新前会生成包含受管项目源码的完整回退点，新增文件和旧文件残留也会在回滚时精确处理；默认保留最近 2 个回退点；
- 源码覆盖完成后，会在当前 Web 使用的 Python 环境中执行 `python -m pip install --editable .`，刷新已安装的 `cfquant` 包元数据；
- 页面更新结果会显示可编辑安装是否执行成功、使用的 Python 和安装后版本；
- 失败时按更新前备份恢复；
- 更新和回滚期间会暂时锁定网页新委托，已进入处理的网页交易请求会先完成后再替换文件；
- 更新后会自动调用项目根目录的 `restart_cfquant.bat`，按“停止 Web/PipeHub、等待端口释放、启动 Web”的顺序恢复服务；LTtx 按既有策略保留运行。

QMT 核心更新：

- 面向每个已绑定 QMT 的 `bin.x64/cfquant/`；
- 用于更新 QMT 侧可导入的 `cfquant` 核心包；
- 不直接替换 QMT 里的加密入口脚本。

账号初始化或保存绑定时也会复用同一套目标目录解析和备份逻辑：用户可以填写 QMT 安装目录、`bin.x64` 或相邻 `python` 目录，系统会解析到 `bin.x64/cfquant/` 并自动复制当前本地核心包。复制失败不会丢失账号配置，页面会提示具体异常，修正目录或权限后重新保存即可。

更新后的提醒：

- 完整项目更新会在覆盖核心包后提示并重新启动对应 QMT 入口。
- 完整项目更新会先关闭已绑定且正在运行的 QMT，再按绑定模式覆盖对应的 `qmt_scripts/CFQUANT*.py` 入口文件。
- QMT 入口文件由项目更新流程按绑定目录覆盖；如果目标目录不可写，更新结果会报告对应失败。

## 回滚

Web 项目更新会保留更新前备份。发生问题时可以在 Web“设置 - 更新管理”中选择备份回滚。

回滚后同样需要注意：

- Web 项目会自动调用 `restart_cfquant.bat` 重启，等待健康检查恢复；
- 回滚源码后也会重新执行 `python -m pip install --editable .`；
- 如果回滚涉及 QMT 核心包，需要重启 QMT 侧入口脚本；
- 回滚会先关闭已绑定且正在运行的 QMT，再按回滚版本覆盖对应入口文件。

交易安全边界：

- 完整项目更新会自动停止已绑定且正在运行的 QMT，再开始覆盖 Web、核心包和入口文件。
- 网页更新保护只覆盖本 Web 服务的新委托和撤单请求，不能强制停止已经运行的 QMT 策略、外部 Python 程序或其他直接连接 QMT 的交易进程；
- 如果更新过程中服务意外退出，重新启动 Web 后仍可在“更新管理”中使用已经落盘的回退点恢复。
