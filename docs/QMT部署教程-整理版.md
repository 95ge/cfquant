# CFQuant QMT 部署教程（整理版）

> 适用于在大 QMT 中部署 CFQuant，并通过本地 Web 控制台或外部 Python 调用行情、查询和交易能力。
>
> 更新时间：2026 年 9 月 4 日。新用户请优先完成通用模式部署，再根据实际需求选择极致模式或高级模式。

## 先选部署模式

| 模式 | QMT 入口脚本 | QMT 数量 | 适用场景 |
|---|---|---:|---|
| 通用模式 | `CFQUANT_CTYPE_ALL_LOWLAT.py` | 1 个 | 默认推荐。部署简单，适合大多数查询、行情和交易场景。 |
| 极致模式 | `CFQUANT_LITE.py` | 1 个 | QMT 对 Python 包导入有限制，无法正常导入 `cfquant` 包时使用。 |
| 高级模式 | 普通端 `CFQUANT.py`；极速交易端 `CFQUANT_TRADE_LOWLAT.py` | 2 个 | 需要进一步降低下单、撤单链路延迟时使用。 |

**兼容性提醒**

- 国泰君安、国泰海通的 QMT 建议使用极致模式。
- 国泰海通不支持高级模式部署。
- 高级模式部署复杂，建议先跑通通用模式。
- 高级模式的延迟通常指外部程序到 QMT 内部的请求链路，不代表 QMT 到交易所的实际报单延迟。

## 一、部署前统一准备

### 1. 准备本地服务

任选一种方式启动本地服务：

```powershell
# 已通过 pip 安装
cfquant --open-browser

# 源码部署
start_cfquant.bat
```

服务启动后，打开本地 Web 控制台：

```text
http://127.0.0.1:8765/
```

### 2. 准备 QMT Python 环境

1. 打开 QMT 并完成账号登录。
2. 在“模型研究”或“模型交易”中确认 Python 环境已经下载并可用。
3. 需要导入 `cfquant` 包的模式，请在 Web 初始化或绑定页填写 QMT 安装目录或 `bin.x64`，系统会自动复制核心包。

对于通用模式和高级模式，建议目录关系如下：

```text
QMT 安装目录/
  bin.x64/
    cfquant/                         # CFQuant 核心包
  python/
    CFQUANT_CTYPE_ALL_LOWLAT.py      # 通用模式
    CFQUANT.py                       # 高级模式普通端
    CFQUANT_TRADE_LOWLAT.py          # 高级模式极速交易端
```

入口脚本会优先查找相邻的 `bin.x64`、`python` 和父目录。Web 保存账号配置时会把当前项目的 `cfquant/` 自动复制到 `bin.x64/cfquant/`；如果目录不存在或权限不足，页面会提示异常，修正目录后重新保存即可。

通过 pip 安装后，可先导出随包附带的 QMT 脚本：

```powershell
cfquant qmt-scripts --output D:\QMT\cfquant
```

极致模式使用的 `CFQUANT_LITE.py` 是自包含脚本，不需要在 QMT 侧导入 `cfquant` 核心包。

### 3. 创建 Python 策略

在大 QMT 中进入“模型研究”，依次选择“新建策略”和“Python 策略”，再将当前模式对应的入口脚本作为策略内容加载。

![创建 QMT Python 策略](image-6.png)

## 二、通用模式部署

通用模式是默认推荐方案。一个 QMT 加载一个 `CFQUANT_CTYPE_ALL_LOWLAT.py` 即可完成行情、查询、下单、撤单和回调能力接入。

### 步骤 1：填写 QMT 目录并放置入口脚本

在 Web 初始化或“绑定”页面填写 QMT 安装目录或 `bin.x64`，保存后系统会自动把当前项目的 `cfquant/` 复制到 `bin.x64/cfquant/`。

将 `qmt_scripts/CFQUANT_CTYPE_ALL_LOWLAT.py` 放到 QMT 的 Python 策略目录或直接粘贴到新建的 Python 策略中。

![CFQuant 核心目录位置](image-4.png)

### 步骤 2：确认 QMT Python 环境

登录 QMT，并确认 QMT 的 Python 环境已经安装。已安装时可跳过此步骤。

![QMT Python 环境](image-5.png)

### 步骤 3：加载并启动策略

在新建的 Python 策略中加载 `CFQUANT_CTYPE_ALL_LOWLAT.py`，保存后启动策略。

![启动通用模式策略](image-7.png)

### 步骤 4：重启 QMT

首次部署或替换核心包、入口脚本后，建议完整重启一次 QMT，再重新启动策略。

![重启 QMT](image-9.png)

### 步骤 5：在 Web 控制台绑定账号

进入 Web 控制台的“绑定”页面：

1. 填写资金账号。
2. QMT 目录填写对应终端的安装目录或 `bin.x64` 目录。
3. 运行模式选择“通用模式”或 `ctypes`。
4. 保存时页面会提示核心包自动复制结果；保存后执行“验证”。

![通用模式账号绑定](image-10.png)

### 步骤 6：验证部署结果

部署成功后，网页端应能看到通用端在线，并能读取资产、持仓、委托或行情数据。

![通用模式部署成功](image-8.png)

最后在“接口调试”或外部 Python 程序中执行一次查询测试。

![接口调用测试](image-14.png)

## 三、极致模式部署

极致模式面向无法正常导入 `cfquant` 包的 QMT 环境。QMT 侧只运行 `CFQUANT_LITE.py`，脚本内部已经包含通信和 `ctypes` 交易桥逻辑。

### 步骤 1：准备极致模式入口

将 `qmt_scripts/CFQUANT_LITE.py` 复制到 QMT 可加载的 Python 脚本目录，或粘贴到新建的 Python 策略中。

> 不需要把 `cfquant/` 核心包复制到 QMT。极致模式仍需要本机 Web 服务和 PipeHub 保持运行。

![复制项目目录](image-4.png)

### 步骤 2：加载并启动策略

在 QMT 的“模型研究”中创建 Python 策略，加载 `CFQUANT_LITE.py` 并启动。

![创建极致模式策略](image-11.png)

![启动极致模式策略](image-12.png)

### 步骤 3：重启并绑定账号

首次部署或更新入口脚本后，重启 QMT 并重新启动策略。

![重启 QMT](image-9.png)

然后在 Web 控制台“绑定”页面选择“极致模式”或 `lite`，填写账号和对应 QMT 核心目录并保存。

![极致模式账号绑定](image-13.png)

### 步骤 4：确认版本和接口可用

QMT 日志中应能看到极致模式入口版本和运行时版本上报。回到网页左上角的版本信息弹窗，确认已显示当前 QMT 的核心版本、入口脚本和入口版本。

完成后，在网页接口调试页执行查询或交易测试。

![极致模式接口调用测试](image-15.png)

## 四、高级模式部署

高级模式使用两个 QMT：一个普通端处理行情和查询，另一个极速交易端处理低延迟下单、撤单和交易回调。

> 不要在同一个 QMT 中同时运行 `CFQUANT.py` 和 `CFQUANT_TRADE_LOWLAT.py`。

### 步骤 1：准备两个 QMT 终端

- **普通 QMT**：加载 `qmt_scripts/CFQUANT.py`。
- **极速交易端 QMT**：加载 `qmt_scripts/CFQUANT_TRADE_LOWLAT.py`。

两个 QMT 都需要安装并登录，且都应能导入 `cfquant` 核心包。Web 会在保存账号配置时分别把核心包复制到两个 QMT 的 `bin.x64/cfquant/`。

![准备两个 QMT](image-16.png)

### 步骤 2：填写两个 QMT 目录并放置入口脚本

在 Web 绑定页选择高级模式，分别填写普通端和极速交易端的 QMT 安装目录或 `bin.x64`。保存后系统会自动复制核心包；普通端和极速交易端仍需分别放置对应的入口脚本。

![高级模式项目文件准备](image-17.png)

![复制 CFQuant 核心目录](image-4.png)

### 步骤 3：创建并启动两端策略

分别在两个 QMT 中创建 Python 策略：

| QMT 终端 | 加载脚本 | 主要职责 |
|---|---|---|
| 普通端 | `CFQUANT.py` | 行情、资金、持仓、委托、成交和状态查询。 |
| 极速交易端 | `CFQUANT_TRADE_LOWLAT.py` | 低延迟下单、撤单和交易回调。 |

![高级模式创建策略](image-18.png)

![启动两个 QMT 策略](image-7.png)

### 步骤 4：重启 QMT 并完成账号绑定

重启两个 QMT，确认两端策略均已重新启动。

![重启 QMT](image-9.png)

在 Web 控制台“绑定”页面选择“高级模式”或 `LTtx`。账号配置应对应普通 QMT，网页状态中应同时显示普通端和极速交易端的运行情况。

![高级模式账号绑定](image-19.png)

### 步骤 5：验证两端状态和接口

部署完成后，确认：

- Web 控制台可正常访问。
- 普通 QMT 的 `CFQUANT.py` 在线。
- 极速交易端 QMT 的 `CFQUANT_TRADE_LOWLAT.py` 在线。
- 账户资产、持仓、委托、成交查询可用。
- 下单、撤单请求由极速交易端处理。

![高级模式状态确认](image-8.png)

![高级模式双端状态](image-20.png)

![接口调用测试](image-14.png)

非开盘时间可以使用低延迟测试页面检查当前链路表现。实际结果会受到电脑性能、QMT 环境和本机负载影响。

![低延迟测试结果](image-21.png)

## 五、部署完成检查清单

- [ ] 本地 Web 控制台可访问。
- [ ] 当前模式对应的 QMT 入口脚本已启动。
- [ ] 通用模式只运行 `CFQUANT_CTYPE_ALL_LOWLAT.py`。
- [ ] 极致模式只运行 `CFQUANT_LITE.py`。
- [ ] 高级模式的两个脚本运行在两个不同的 QMT 中。
- [ ] Web 绑定页中的账号、QMT 目录和运行模式正确，并且核心包自动复制提示无异常。
- [ ] 版本信息页面已收到 QMT 运行时版本上报。
- [ ] 已完成至少一次资产、持仓、委托或行情查询测试。

## 六、常见问题

### QMT 日志提示无法导入 `cfquant`

通用模式和高级模式需要 QMT 能找到核心包。优先检查 Web 保存账号配置时的自动复制提示、`bin.x64/cfquant/` 是否存在，以及入口脚本和核心包是否属于同一版本。对于存在 Python 包白名单限制的终端，请改用极致模式。

### 网页能打开，但账号状态一直未上线

确认本地服务仍在运行、QMT 策略已经启动，并检查 Web 绑定页中的 QMT 核心目录和运行模式。更新入口脚本或核心包后，需要重启对应的 QMT 策略。

### 高级模式只有一端在线

检查是否误将两个高级模式脚本加载到同一个 QMT。普通端必须运行 `CFQUANT.py`，极速交易端必须在另一个 QMT 中运行 `CFQUANT_TRADE_LOWLAT.py`。

### 更新后版本信息不一致

Web 项目、QMT 核心包和 QMT 入口脚本需要按本次发布内容同步更新。更新后重新启动本地服务，再重启相关 QMT 和策略。
