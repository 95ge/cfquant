# QMT 交易日自动重启与登录

QMT 登录后策略异常停止的检测与恢复，参见 [QMT 策略自动恢复](QMT策略自动恢复.md)。

新绑定默认开启“自动启动并按交易日重启 QMT”、“允许 QMT 自动更新”、“自动导入并管理 QMT 策略”和“QMT 启动后自动运行”。默认在每个 A 股交易日北京时间 **09:00** 重启，周末和法定休市日不执行计划重启。项目负责启动绑定目录的终端，登录方式由“自动输入账号和密码”决定。自动更新只处理已确认属于该绑定 `XtUpdate.exe` 的更新窗口。

关闭“允许 QMT 自动更新”时，版本提示会选择“否”，不安装新版本。开启后，项目通过更新程序的原生 `WM_COMMAND` 处理程序选择“是”，等待下载和安装完成，在“安装完毕，是否立即运行”提示中选择“否”，确认安装程序退出后再启动绑定目录的 `XtItClient.exe`。随后使用新 PID 重新登录。整个过程不发送鼠标、键盘、坐标或前台激活事件；窗口标题、控件 ID、进程完整路径和父子进程关系任一不匹配，都会停止并保留给人工处理。

“自动输入账号和密码”默认勾选，旧配置缺少该字段时也按开启处理。勾选时，QMT 目录、登录账号和登录密码均为必填。绑定、首次初始化和新手引导都会在关闭 QMT 前校验，后端也会独立校验；缺少信息不能保存。此模式会清空原登录框，使用绑定中保存的账号和密码，适合需要补填密码的客户端。编辑已有绑定时，登录账号和目录不变可留空复用已保存的加密密码；更换账号或目录后需重新填写对应密码。

如果 QMT 已能自行自动登录，可取消勾选“自动输入账号和密码”。仍需填写 QMT 目录，项目继续负责启动、手动重启和交易日定时重启，但不会注入登录组件、解密密码、改写登录框或点击登录，也不要求填写登录账号密码。请先在 QMT 内开启并验证自动登录；仅“记住密码”并不保证自动提交，必要时仍需人工点击登录。此模式显示“由 QMT 自行登录”，不会仅凭进程已启动就标记“已登录”；策略是否就绪仍以绑定连接状态为准。

开关保存在 `qmt_auto_login.auto_fill_credentials`，更新策略保存在 `qmt_auto_login.auto_update`，缺少更新字段的旧配置按关闭处理。取消勾选不会删除此前保存的加密密码；重新勾选后，账号和目录不变时仍可复用。只使用 QMT 自行登录时无需满足 Qt 组件登录的版本限制或安装其注入依赖。

### 旧配置的一次性迁移

加载配置时，只有配置中记录的 `saved_core_version`（兼容 `core_version`）能确认低于 **0.2.59**，才将上述四个开关统一开启，包括此前明确关闭的选项。等于或高于 0.2.59，以及版本缺失、无法识别的旧配置，均保留原选择；不会通过当前安装版本、QMT 版本或文件时间猜测旧配置版本。以后保存配置时会记录实际运行的核心版本。

迁移前在配置文件旁保留 `.before-qmt-automation-0.2.59.bak` 备份，成功后写入 `qmt_automation_defaults_migration` 并记录迁移数量。迁移只执行一次，之后手动取消勾选不会被再次开启。迁移失败时保留原配置，下次加载重试。绑定整体的启用状态、模拟/实盘模式、自动输入密码选择、账号密码和自定义重启时间不会因此改变；缺少重启时间字段时补充 09:00，明确保存的空列表继续关闭定时重启。

## 使用方式

在绑定设置中填写 QMT 安装目录、QMT 登录账号和登录密码，勾选“自动启动 QMT”，确认交易日重启时间后保存。登录账号是客户端登录界面使用的账号，可能不同于绑定资金账号。已有绑定的自定义时间和明确保存的空时间列表继续保留；原来没有计划重启的绑定可以添加 `09:00`。删除全部时间可关闭计划重启。

项目需要保持运行。服务器使用的时区不影响计划时刻，调度统一采用北京时间。程序重启后可补执行最近 10 分钟内错过的计划，避免正常轮询延迟造成漏跑；不会在中午启动项目时补执行早晨的重启。

新功能需要重启项目后加载。运行环境的 Windows 依赖已加入 `requirements.txt` 和包依赖：`frida==17.16.4`、pywin32；Qt 组件代理也已纳入发行包。Web 的原生环境预检和 Frida 登录操作在独立子进程中执行，兼容性失败不会终止控制台。依赖修复及手动运行方式见 [QMT 组件登录工具](QMT组件登录验证.md)。

## 每次重启

1. 勾选自动输入时，验证组件自动登录所需依赖、客户端版本和已保存密码的解密能力；取消勾选时跳过此检查。仅 Qt 版本暂未适配时，降级为本次手动登录，仍可启动 QMT。
2. 按可执行文件的完整路径精确查找该终端，强制结束旧进程及其子进程，轮询确认退出后才启动新进程。无法查询进程或旧进程未退出时，停止本次启动并显示原因。
3. 如果取消了自动输入，由 QMT 自行登录，项目不执行后续组件登录操作。若本次因 Qt 版本暂未适配而降级，则提示手动登录。其余勾选自动输入的情况，等待新进程的登录组件就绪，清空原有账号和密码，重新填入绑定中配置的账号；即使账号相同也重新填写。
4. 填入绑定中保存的密码后提交一次，不尝试客户端记住的密码，也不在密码被拒绝后连续重试。
5. 确认对应登录用户的主界面出现后记录“已登录”，之后由现有的 QMT 自启动策略继续建立项目连接。

登录组件调用在 QMT 自己的界面线程上执行，不依赖模拟鼠标、键盘、坐标或剪贴板。客户端自己可能在登录完成时激活窗口。

计划重启、手动重启都会结束旧进程，即使旧登录任务尚未结束。自动填写可用时，项目启动若发现残留 QMT，也先结束后重新打开；如果已检测到 Qt 版本暂未适配，普通启动请求保留正在运行的终端，避免打断手动登录。重复的普通启动请求会等待同一个正在进行的任务；旧任务的迟到结果不会覆盖新任务的状态。登录出现验证码时先尝试读取并填写；读取失败会结束旧进程、重新启动 QMT 并重试一次登录，仍失败时显示原因并交给人工处理。

同一安装目录在同一交易日、同一计划时刻只执行一次，即使有多个绑定或 Web 服务中途重启。登录失败会显示失败原因，不会取消未来交易日的计划。网络超时、验证码和未知错误不会触发连续密码尝试；验证码重试只会重启一次客户端。

## Qt 升级后的手动登录降级

当依赖和凭据检查通过、Core/Widgets 文件版本一致、客户端为 x64，但 Qt 版本尚未适配时，仍会启动绑定 QMT。界面显示黄色“等待手动登录”，并提供检测到的 Qt 版本与原因；本次暂停自动填写账号密码和点击登录。已在运行的终端不会因重复普通启动请求而被反复重启。

该处理只改变本次运行状态，保留“自动输入账号和密码”、已保存的加密密码、自动更新选择及交易日重启计划。手动或计划重启仍按原设置执行一次，随后等待人工登录。登录完成和策略连接情况请以 QMT 界面及绑定在线状态为准；降级状态不会凭进程存在就自动改为“已登录”。

QMT 自动更新后也会重新检查新进程的兼容性；新版本不支持时同样降级，同一进程不会反复尝试组件登录。降级后继续观察启动阶段的更新窗口约 90 秒，已开始的更新继续按既有超时策略处理。更新生成新 PID 后重新检查；恢复到受支持的组件版本或安装相应 CFQuant 适配更新后，下次启动可恢复自动填写。

此降级仅处理明确识别出的“Qt 版本未适配”。密码缺失或无法解密、Frida/pywin32 依赖异常、Core/Widgets 混装、32 位客户端及文件损坏仍需先修复。跨 Qt 主版本后若组件名称或安装结构发生变化，也可能需要专门适配。

## 密码与状态

密码使用 Windows DPAPI 按当前 Windows 用户加密，保存在运行配置目录的 `qmt_login_credentials.json`，与普通账号配置分开。普通配置接口只返回登录账号及“已保存密码”标志，不返回明文或密文。密码输入框留空保留原密码；输入新密码则替换。

输入密码时可点击“显示密码／隐藏密码”。编辑已有绑定时，点击“查看已保存密码”才通过专用接口读取该绑定的密码；接口沿用账号配置的访问认证，并禁止缓存。仅查看不会重新提交或覆盖密码，明文不进入页面全局状态、浏览器持久存储或日志；隐藏已保存密码、修改账号／目录、关闭窗口时清空显示。迟到的读取响应不会填入关闭后重新打开的表单。

换机器或换 Windows 运行用户后，需要重新保存密码。此限制来自 [Windows DPAPI 的用户与机器绑定](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata)。

绑定列表和启动提示显示启动、登录中、已登录及失败状态。“已登录”表示 QMT 客户端认证完成；策略桥接是否在线仍由原有连接状态显示。

## 验证与适用范围

- 已实测国金模拟 `2.1.19.200` 和华泰模拟 `2.1.19.1` 的组件登录，它们使用 Qt 5.6.2 x64。
- 已适配国金模拟 `2.1.36.0` / Qt 5.15.2 x64，并通过管理接口实测完整重启、自动填写保存的账号密码、单次提交及登录成功；历史失败状态已清除，其余运行中的 QMT 保持不变。
- 华泰已验证最小化窗口下的已有密码直接登录、空密码补填登录。
- 集成后的华泰模拟端已实测完整重启链路：旧进程 84560 退出，新进程 76836 启动并登录成功，其余三个 QMT 进程未改变。
- 自动化测试覆盖节后首个交易日、周末调休仍不交易、前次失败不阻断下一交易日、同目录去重、项目重启后的去重、旧进程退出失败、密码不泄露到配置或接口，以及桌面和手机宽度的表单行为。

交易日历使用项目现有的 `pandas-market-calendars` SSE 日历。超过已公布休市数据的年份会明确报错，避免把节假日当作交易日；需要随节假日公告更新依赖。2026 年国庆后首个交易日为 10 月 8 日，10 月 10 日周六仍休市，参见 [上交所公告](https://www.sse.com.cn/disclosure/announcement/general/c/c_20260915_10832273.shtml)。

当前自动登录组件支持 Qt 5.6.2.0、5.15.2.0 x64，并核对文件版本、实际加载目录及运行中 Qt 版本。明确识别的未适配版本按上述规则降级；混合组件或更新未完成时给出组件诊断。其他券商内部组件变化、验证码、锁屏、远程桌面断开或开机无人登录 Windows 的环境仍需要相应验证。此功能不会自动解决 Windows 会话启动问题。

实现入口：`cfquant_web_server.py` 的自动启动、重启调度与登录任务；`cfquant/qmt_update.py` 的更新进程监控、原生窗口命令和安装后重启；`cfquant/qmt_component_login.py`、`cfquant/qmt_component_agent.js` 的组件操作；`cfquant/qmt_credentials.py` 的密码保存。
