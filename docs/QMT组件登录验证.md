# QMT 组件登录工具

`tools/qmt_component_login.py` 根据绑定名称选择正在运行的 QMT，在其 GUI 线程上直接操作 Qt 密码组件并调用登录方法。它不使用模拟键盘、鼠标、坐标定位或剪贴板。

组件实现现已接入网页的自动启动与交易日重启服务，参见 [QMT 交易日自动重启与登录](QMT交易日自动重启与登录.md)。命令行工具本身仍不启动或退出 QMT；配置了登录账号时会核对或设置该账号。

以上两个历史验证终端使用 Qt 5.6.2 x64。2026-11-17 新增国金模拟 `2.1.36.0` / Qt `5.15.2.0` x64 适配，已实测识别登录窗口、覆盖填写保存的账号密码、单次提交及进入对应账号主界面。

自动登录目前支持 Qt `5.6.2.0` 和 `5.15.2.0` x64。工具检查 Core/Widgets 文件版本一致性、实际加载模块目录，以及已加载 Qt 的构建版本；更新后磁盘文件与运行中组件不一致时，提示正常退出并重启该绑定。对象列表读取增加容量边界检查。

明确识别到未适配的 Qt 版本时，独立命令行工具停止组件操作并报错；网页启动服务仍会启动或保留 QMT，并显示“等待手动登录”，本次暂停自动填写，保留用户原来的自动登录设置。更新产生新进程后重新检查兼容性，同一进程不反复尝试登录。DLL 混装、32 位客户端、依赖故障和凭据异常不按版本降级处理。完整行为见 [Qt 升级后的手动登录降级](QMT交易日自动重启与登录.md#qt-升级后的手动登录降级)。

华泰第一次已有密码测试已进入主界面，但早期结果检测在登录途中遇到暂时隐藏的密码框而报错，随后独立检查确认已经登录。该状态处理已修正，之后的空密码实测完整返回 `logged_in`、`attempts=["provided"]`、`minimized_before=true`、`script_errors=[]`。

当前强制重启、覆盖账号和密码、单次提交及旧任务隔离逻辑通过自动化测试验证。错误识别仅覆盖已定义的界面提示，密码被拒绝、未知提示和超时均不会自动连续重试。

## 使用

本机验证依赖：Python 环境中的 Frida 17.16.4、pywin32 306、psutil 5.9.8。Windows 安装依赖已固定为 `frida==17.16.4`，`pyproject.toml`、`requirements.txt` 与组件修复命令使用同一版本。

Frida 17.25 引入的新 Windows 注入实现，在部分 Windows 版本上会触发 `Unable to locate the ntdll loader TLS routines` 并直接终止调用进程。仅能导入模块不足以证明兼容；项目在导入 Frida 前校验版本，未经本项目验证的版本停止自动操作并给出修复提示。上游问题与修复记录：<https://github.com/frida/frida-gum/issues/1203>。

通过 `start_cfquant.bat` 启动时，即使 cfquant 主包版本一致，也会检查 Frida 版本；不匹配时使用本次启动选择的 Python 安装 `frida==17.16.4`。已匹配时不重复安装。安装失败或超过 120 秒会提示并继续启动 Web，用户可手动登录和启动策略。直接运行 Web Python 入口时只检测并提示，不自动修改依赖。

Web 的登录环境预检、Frida 登录操作和策略恢复操作均在隐藏的独立子进程中执行。子进程异常退出、调用超时不会终止 Web；不重放结果不确定的登录或策略启动操作。密码只通过子进程标准输入传递，不放入命令行、文件或日志。取消登录会结束对应子进程；Web 退出导致输入管道断开时，子进程也会退出。

需要关闭原生自动化时，可在项目目录的 PowerShell 中执行：

```powershell
$env:CFQUANT_QMT_AUTOMATION = "0"
.\start_cfquant.bat
```

此开关关闭 Frida 组件登录、环境原生预检和策略原生恢复，并跳过启动时的 Frida 自动安装。它不关闭行情、交易接口，也不等同于关闭 QMT 进程启动和部署管理。若需完全手动管理 QMT 的启动与重启，同时设置 `$env:CFQUANT_QMT_AUTO_START = "0"`。恢复时移除对应环境变量并重启项目。网页组件检测和下述探测命令只读取环境。

项目启动时会用实际运行 Web 服务的 Python 解释器检查 `frida`、`win32api`、`win32crypt`、`win32event`、`win32gui` 和 `win32process` 是否可以导入。检查只读取环境，不会在每次启动时强制重装；版本已满足但 DLL 已损坏或与旧文件冲突时也会明确报告。网页的“自动登录组件检测”会显示解释器路径、环境类型、失败模块和修复命令，可复制到同一台电脑的 PowerShell 执行。Conda 环境使用绑定当前前缀的 `conda install --prefix ... --force-reinstall` 命令；venv 和普通 Python 环境都使用探测到的解释器执行 `python -m pip`，只有普通 Python 环境会附带 `pywin32_postinstall`，venv 不运行该脚本。依赖异常时可以选择改为手动启动并登录 QMT，绑定配置仍可继续使用。

Python 3.8–3.10 的外部 Web 服务需要 `typing_extensions>=4.4`。Frida 17.16.4
虽然声明支持旧版 Python，但直接从标准库导入了新版类型标注，可能出现
`cannot import name 'NotRequired' from 'typing'`，更早的 Python 还可能缺少 `ParamSpec`。
CFQuant 在组件检测和实际自动化加载时，为 Frida 的同步、异步 Python 模块使用
`typing_extensions`，不修改 Frida 安装文件，也不向标准库 `typing` 添加成员。
Python 3.11 及以上沿用原生类型标注。

遇到上述错误，应更新包含此修复的 CFQuant；只重装相同版本的 Frida 或只安装
`typing_extensions` 不会改变旧版 CFQuant 的导入方式。兼容依赖缺失或过旧时，
检测页会生成绑定当前解释器的安装、升级命令。只有 pywin32 检测失败且使用独立
Python 时，才需要执行对应的 `pywin32_postinstall`；仅 Frida 失败时无需运行它。
这里的 Python 指外部 Web 服务解释器，QMT 内置 Python 3.6 无需切换。

先启动对应 QMT，然后从项目目录执行：

```powershell
python tools/qmt_component_login.py --binding 华泰模拟测试 --prompt
```

绑定名称必须与 `runtime/config/cfquant_web_config.json` 中的 `display_name` 精确一致。也可通过 `--config` 指定其他配置文件。

尚未登录时，工具始终读取调用方提供的密码并覆盖密码框内容。`--prompt` 从终端读取密码且不回显；没有该参数时从标准输入读取一行，便于调用程序通过管道传入。没有密码命令行参数，不应将密码写入命令文本。

可用 `--report <文件路径>` 保存不含密码和登录用户名的结果；`--timeout` 控制单次提交后的观察时长，默认 40 秒。工具退出码为 0 表示检测到登录主界面，其他结果为 1，运行环境或组件异常则停止并报错。

## 登录流程

1. 按绑定的安装目录精确匹配唯一进程，并用进程互斥锁阻止本工具并发提交。
2. 已经处于主界面时返回 `already_logged_in`，不再提交。
3. 登录中或已有网络错误提示时停止并报告；出现验证码时先尝试从登录界面读取并填写。
4. 配置了登录账号时，清空账号和密码，重新设置该账号；账号相同也执行覆盖。不读取客户端记住的密码。
5. 取得调用方提供的密码后调用 `QLineEdit::setText()` 覆盖密码框，再调用 `CLoginDialog::slot_loginClicked()`。网页自动登录从加密存储读取绑定密码。
6. 最多提交一次，密码被拒绝时停止。未提供密码时返回需要密码，不尝试客户端记住的值。
7. 网络异常、超时或未知提示不触发第二次登录；验证码读取成功后继续提交登录。

验证码处理为保守的自动化尝试：原生组件只使用登录界面明确暴露的验证码文本，不猜测图片内容。验证码无法读取时返回挑战状态，由 Web 登录任务结束当前 QMT 进程并重新启动一次后重试登录，仍无法通过时保留人工处理。
8. 仅在目标进程出现对应登录用户名的 Qt 主窗口时报告本次登录成功。不会把调用登录方法本身当作成功。

登录用户名与绑定资金账号可能不同。配置了登录账号时，工具使用配置值；独立命令行工具未配置该值时使用当前选中用户。读取用户名仅用于内存中的主窗口匹配，操作期间发生其他账号切换则停止。该判断确认客户端登录界面已完成，不代替逐个交易账户的连接、权限或行情可用性检查。

## 实现与边界

`cfquant/qmt_component_agent.js` 经 Frida 临时加载到选定进程，定位 Qt 对话框和密码控件，并将调用安排到目标 GUI 线程。结束后解除附加，不修改磁盘上的 QMT 模块。

不依赖前台焦点，但客户端自身可能在登录完成后激活窗口。窗口最小化已经验证；锁屏、远程桌面断开、没有物理显示器、开机无人登录 Windows 或服务 Session 0 场景尚未实测，不能由本次结果推断这些环境全部可用。

依赖内部导出方法和 Qt 对象布局，当前支持范围是上述已验证组合，其他券商的登录组件仍需单独验证。

策略分支测试：

```powershell
python -m pytest cfquant/tests/test_qmt_component_login.py cfquant/tests/test_qmt_login_compatibility.py -q
```

测试涵盖覆盖已有密码、填入空密码框、账号相同仍覆盖、密码被拒绝后停止、已登录不重复提交，以及超时、网络问题、验证码、组件启动和登录进行中的状态处理。
