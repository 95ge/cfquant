# CFQuant 文档维护规范

## 文档分区

`docs/` 只保存可以面向用户或公开开发者发布的内容，包括 API、兼容性、部署、运维、功能说明和版本日志。

产品方案、UI 初稿、架构设计、协议草案、实现计划、性能诊断、安全/授权设计、企业私有化方案和未发布功能，统一放入本地 `private/设计文档/`。该目录默认被 Git 忽略，不随公开源码和公开发布包提交。

## 公开化要求

内部文档转为公开文档前，需要删除或泛化：

- 真实服务器地址、目录、账号、资金账户和内部服务名称；
- 密钥、令牌、密码、日志和数据库内容；
- 未发布的收费、授权、风控和部署细节；
- 只适用于开发环境的进程、端口和调试步骤。

公开文档必须可以脱离内部工作区阅读，链接不能依赖私有目录。内部方案需要提供用户说明时，先提炼稳定的功能行为、限制和配置方法，再放入 `docs/`。

## 新文档检查

新建文档时先确定它的读者和发布范围，并在文首写明版本、日期和状态。提交前检查：

```powershell
git status --short --untracked-files=all
git check-ignore -v private private_docs
git diff --check
```

涉及交易、远程控制、行情转发、授权或数据保留的文档，还要写明权限、失败语义、审计、限流、回滚和本地功能在官网不可用时的行为。

完整的内部归档、评审和公开化流程见私有设计文档中的项目规范。
