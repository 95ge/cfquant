# QMT 虚拟机与 MAC 设置

进入 **账号绑定 → 编辑 → 虚拟机与 MAC 设置 → 设置**：

- **禁用 QMT 虚拟机检测**：启用当前 QMT 进程的虚拟机检测适配。
- **启用 MAC 注入**：让当前 QMT 进程的网卡信息采集使用填写的 MAC 地址。
- **注入的 MAC 地址**：可编辑并保存。接受 `02-11-22-33-44-55` 或 `02:11:22:33:44:55`，保存为大写短横线格式；拒绝全零和组播地址。启用注入时不能为空。

新绑定和缺少这些字段的旧绑定均默认关闭两项功能，MAC 默认为空。两个开关独立；关闭注入后仍保留已填写的地址。共用同一 QMT 安装目录的启用绑定需要保持生效设置一致。

保存绑定时沿用已有的 QMT 退出和部署流程。配置在下一次通过 cfquant 启动或重启对应 QMT 时生效，包括自动启动、计划重启、网页启动、更新完成后的启动和运行库切换后的启动。直接使用 QMT 快捷方式启动不会应用这些设置。启用功能本身不会开启“自动启动”。

配置按绑定保存在 `qmt_vm` 字段中，可通过原有 `/api/account-config` 接口提交；省略字段的编辑保留已保存的设置：

```json
{
  "qmt_vm": {
    "disable_vm": false,
    "inject_mac": false,
    "mac_address": ""
  }
}
```

主项目的实现位于 `cfquant/qmt_vm_*.py`、`cfquant/qmt_vm_agent.js`、`cfquant/qmt_mac_agent.js`，无需依赖项目内的内部启动器源码目录，独立项目保持原样。`pefile` 随主项目依赖安装，UPX 及许可文件随安装包附带。

启用后，独立后台进程先创建暂停的 QMT、安装指定钩子，再恢复运行。Web 重载不会主动撤销运行中的钩子；QMT 退出后后台进程自行退出。未完成启动确认时只清理本次新建的进程，不根据历史 PID 终止其他程序。

虚拟机适配不设置 QMT 版本号白名单，仍需唯一识别函数并核对内存入口；无法识别时明确报错，不继续以未适配状态启动。只启用 MAC 注入时不识别或修改虚拟机检测函数。MAC 注入只修改目标 QMT 的网卡采集结果，不修改系统网卡或磁盘上的客户端文件。钩子安装成功不等于券商服务器接受登录，仍以客户端和服务器返回结果为准。

多个券商的实际文件检查结果见 [多券商兼容性检查](qmt_broker_compatibility.md)。没有 MAC 绑定要求时保持 MAC 注入关闭；客户端存在 MAC 采集接口不代表服务端要求绑定。
