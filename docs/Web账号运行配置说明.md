# Web 账号运行配置说明

## 1. 初始化是必需步骤

Web 服务启动后，第一次访问控制台会显示初始化窗口。需要填写：

默认启动命令是 `cfquant run`，然后访问 `http://127.0.0.1:8765/`。如果页面提示需要初始化，填写默认资金账号、账户类型、运行模式及 QMT 目录；网页登录管理默认关闭，只有勾选“启用网页登录管理”时才需要填写管理员账号、密码和确认密码。初始化只创建 Web 运行配置，不会清空已有项目文件。

## 2. 配置和数据位置

源码运行时默认使用项目目录下的 `runtime/`：`runtime/config/cfquant_web_config.json` 保存账号、桥接和初始化状态；`runtime/db/cfquant_web_config.db` 保存 API Key、网页登录密码哈希、设置和持久会话；项目根目录 `log/` 保存服务日志。打包版默认将运行数据放在 Windows 的 `%LOCALAPPDATA%\cfquant\runtime\`，日志放在 `%LOCALAPPDATA%\cfquant\log\`。设置 `CFQUANT_HOME` 或 `CFQUANT_RUNTIME_DIR` 后，可以将运行数据迁移到指定目录。

## 3. 重置网页登录密码

登录后进入“设置”→“Web 访问”→“网页登录”，点击“重置密码并生成文件”。登录页也提供“忘记密码？本机重置并生成文件”，仅允许本机未登录请求使用。服务会生成随机密码、更新密码哈希并立即使旧登录会话失效；新密码只写入项目目录的 `cfquant_web_reset_password.txt`，设置页会持续显示该文件的实际路径，不显示密码。请打开该文件完成重新登录，并在登录后删除文件。若项目目录没有写权限，修复权限后重试。

| 字段 | 说明 |
|---|---|
| 账号 | 默认资金账号，系统默认按单账号运行 |
| 账户类型 | 可选 `STOCK`、`CREDIT`、`FUTURE`、`FUTURE_OPTION`、`STOCK_OPTION`，用于区分普通、信用、期货、期货期权和股票期权账号路由。 |
| QMT 目录 | 可选。可以填写 QMT 安装目录、`bin.x64` 或相邻 `python` 目录；保存后系统会解析到 `bin.x64`，用于区分部署实例、自动复制核心包和后续更新目标；留空会导致自动复制和自动更新不可用 |
| 运行模式 | `ctypes` 通用模式、`lite` 极致模式或 `LTtx` 高级模式 |

初始化成功后，账号、目录和模式会写入 Web 运行配置。保存时如果填写了 QMT 目录，Web 服务会自动把当前项目的 `cfquant/` 核心包复制到对应 `bin.x64/cfquant/`；如果目标目录不存在、路径不是 QMT 核心目录或没有写入权限，页面会提示异常，账号配置仍会保留，方便用户修正目录后重新保存。勾选“自动导入并管理 QMT 策略”后，会进一步生成当前模式的导入包，并配置模型账号、模拟/实盘及启动自运行设置。内部通道 ID 由服务端自动分配。

### 自动导入与模型配置

单个 QMT 运行账号时，保持“同账号独立市场路由”关闭。开启该路由并使用自动导入时，必须为启用的 SH/SZ 市场填写对应 QMT 目录；目录缺失会在保存前报错，不会将不完整配置写入账号。

初始化、账号绑定和新手向导均支持以下设置：

- 自动导入并管理 QMT 策略：新建绑定默认开启，原有绑定不会自动迁移；开启后必须填写 QMT 目录。
- 模型运行方式：新建绑定默认实盘运行；模拟盘必须显式选择“模拟运行”。实盘对应 QMT 模型的 `runMode=1`，不会改变券商登录环境或账号权限。已有绑定会保留原设置。
- QMT 启动后自动运行：默认关闭，对应 `startupAutorun`，不负责启动 Windows、QMT 或自动登录。
- 自动启动 QMT：默认关闭，保存后启动绑定主目录的 QMT；已有设置会保留。它与策略自动运行、QMT 自身自动登录是三个独立设置。
- 主图品种：默认 `SH000300`；独立市场入口按市场选择主图，深圳默认 `SZ399001`。
- 模型账号 Key：优先从目标 QMT 已保存的同资金账号模型识别；没有模型时读取该终端 `userdata/users/*/authAndConfig.xml` 的账号授权记录。未找到或存在歧义时，可分别填写普通端、交易端、SH/SZ 的完整 Key。它不是 Web 的 `account_key`，也不是股东代码。系统不会编造账号 Key。

保存后的弹窗只显示自动部署结果和启动提醒，不再提供策略源码或复制按钮。点击“知道了”即可关闭，也可点击“检测连接”验证通道。账号绑定与首次初始化使用相同流程。

未勾选“自动启动 QMT”时，按提示重启 QMT 并登录；勾选后，在启动的 QMT 中登录即可。QMT 自身已设置自动登录时，等待自动登录完成。**国金证券 QMT 目前不支持自动登录，启动后需手动输入密码登录。** 高级模式和独立市场涉及多个终端时需分别登录，自动启动仅作用于绑定的主 QMT 目录。

首次导入的流程如下，期间保持 Web 服务运行；等待退出、部署错误或账号 Key 缺失时，以部署状态提示为准：

1. 保存绑定。若 QMT 正在运行，网页显示等待正常退出；服务不会强制结束 QMT。
2. QMT 退出后，服务备份 `config/indexUserConfig.xml`，关闭该账号旧 cfquant 模型的自启，把生成的 `.rzrk` 放入 `formulas/` 导入队列，同时创建账号、主图、运行方式及自启设置完整的模型。
3. 等网页显示“导入包和模型已准备”后，启动并登录 QMT。QMT 处理导入并按模型设置运行，不再专门为创建模型要求第二轮重启；未勾选自启时由用户在模型交易中手动运行。
4. 网页依据当前策略代次的运行心跳显示“托管策略已运行”，导入队列文件消失不代表运行成功。若入口加载或初始化异常，部署进度显示具体错误。QMT 日后正常退出时，服务还会核对持久化的策略登记和 Python 容器文件。

只修改模拟/实盘、自启或模型账号 Key 时复用已有策略，无需重复导入。相同账号、终端、市场角色和运行模式始终复用同一个 QMT 模型名；更新入口代码或身份配置时只更新该模型的导入包，不会新增模型。切换通用、极致、高级模式或更换 QMT 终端槽位时，才会生成新的模型槽位。绑定页的“更新 cfquant”也会重试失败的导入任务。修改目录或删除、禁用绑定后，过时任务会撤销，旧托管策略不能重新取得运行资格。

每个终端和资金账号都有独立的托管文件目录 `QMT安装目录/cfquant_managed/`，包含保留的导入包、身份文件、运行锁及 XML 备份。任务进度保存在 `runtime/config/qmt_strategy_jobs.json`，Web 重启后继续执行。QMT 自己生成的 `python/*.py` 是专用容器，不以明文脚本覆盖；不修改 `configFormula`。

### 同账号模式互斥

以 QMT 的实际安装目录和资金账号为范围执行互斥，`bin.x64`、`python` 和安装根目录视为同一个终端。保存新模式会禁用其他冲突绑定；不同资金账号可在同一个 QMT 中各自使用独立的托管通道和身份文件。

托管脚本在创建桥接前获取运行锁。模式切换或绑定禁用后，旧脚本停止处理请求并关闭桥接；已有请求结束、旧运行锁释放后，新模式才能启动。关闭异常时保留锁，拒绝启动第二种模式。同模式的 SH/SZ 入口可按各自角色运行。

这些操作关闭的是 cfquant 交易通道，不能假称已调用 QMT 的“停止模型”按钮。旧版手工导入脚本没有运行锁，首次迁移需正常退出 QMT；离线配置会关闭其自启。迁移后不要再手动运行旧入口。后台不强杀终端，也不操作其他账号或用户自编策略。

导入格式依据本地 QMT 研究资料适配，券商客户端版本仍需实机确认。配置写入、策略导入和实际在线是不同状态，以绑定页部署进度及连接验证结果为准。

“绑定”页面的“重新初始化默认配置”会清空账号运行配置、账号配对和行情数据源选择，但保留内部通道定义。重新加载网页后必须再次完成初始化。

## 4. 三种模式

### 通用模式

通用模式使用 ctypes 单文件桥：

- QMT 侧只加载 `CFQUANT_CTYPE_ALL_LOWLAT.py`；
- PipeHub 负责行情、查询、下单、撤单和回调；
- QMT 落地链路走 PipeHub，不走高级模式的 LTtx 普通/极速双桥；多账号也通过 PipeHub 通道和请求中的 `account_id` 路由；
- 适合快速部署、功能验证和不优先追求极限延迟的场景。

本地 Web 服务启动时会先检查并预启动 `LTtx_server.py`，保存通用、极致或高级模式配置时也会补充检查，确保 `cfquant` Python 库自动发现、高级模式切换和旧 LTtx 客户端随时可接入。这个预启动不改变通用模式的请求路由；通用账号的查询、交易和状态探测仍然走 ctypes/PipeHub。Web 重启、项目更新重载和定时重启会保留 LTtx；只有执行 `stop_cfquant.bat` 完整退出时才停止 LTtx。

如果 QMT 中仍保留并运行 `CFQUANT.py`、`CFQUANT_TRADE_LOWLAT.py` 等高级模式入口，它们会继续尝试连接 LTtx 并输出 LTtx 相关错误。通用或极致模式排查时应先停止这些旧高级脚本，只保留当前模式对应的 `CFQUANT_CTYPE_ALL_LOWLAT.py` 或 `CFQUANT_LITE.py`。

### 极致模式

极致模式是 PipeHub 链路的自包含变体：

- QMT 侧只加载 `CFQUANT_LITE.py`；
- 脚本内部自带协议、双通道桥和 `ctypes` 调用逻辑，不导入 `cfquant` 包；
- 启动后会上报核心版本、入口脚本和入口版本，网页左上角版本弹窗可确认当前 QMT 是否加载了极致模式入口；
- 特别适合国泰君安君弘君智 QMT，以及其他白名单限制、无法导入项目核心包的环境。

极致模式仍需要本机 Web 服务和 PipeHub 在线。启用自动管理后，入口更新由系统部署，按绑定页进度重启 QMT 即可。

### 高级模式

高级模式使用 LTtx 双桥：

- 普通 QMT 加载 `CFQUANT.py`；
- 另一个极速交易端 QMT 加载 `CFQUANT_TRADE_LOWLAT.py`；
- 普通桥主要处理查询和行情，极速桥主要处理交易和交易回调；
- 适合追求更低交易请求延迟的场景。

高级模式必须打开两个不同的 QMT 终端，不能用同一终端的根目录和 `bin.x64` 冒充两个目录。同一资金账号在同一个 QMT 中只能启用一种 cfquant 模式。

高级模式不是全局唯一开关，而是每个账号的首选路由。网页仍保留全局通信模式设置用于兼容旧配置和控制默认启动行为，但已保存账号配置的优先级更高。

## 3. 多账号配置

默认是单账号。配置第二个及以上账号时，每个账号都要单独保存：

1. 资金账号；
2. 账户类型，普通证券账户填 `STOCK`，信用账户填 `CREDIT`，期货填 `FUTURE`，期货期权填 `FUTURE_OPTION`，股票期权填 `STOCK_OPTION`；
3. QMT 目录，建议填写但可留空；
4. 首选模式；
5. 是否作为共享行情数据源；
6. 启用状态。

手工入口可以沿用共用通道的旧配置。开启自动管理后，同一 QMT 内的不同账号也会分配独立内部通道，避免多个模型争用同一请求通道。

保存账号配置时，如果填写了 QMT 目录，Web 服务会先自动复制 `cfquant/` 到对应 `bin.x64/cfquant/`，再在该目录写入 `cfquant_bridge_config.json`。高级模式会同时处理普通端和极速交易端两个 QMT 目录；同账号独立市场路由会分别处理 SH/SZ 子桥目录。`CFQUANT_CTYPE_ALL_LOWLAT.py` 和 `CFQUANT_LITE.py` 启动时都会读取这个文件，获得自己的 `bridge_id` 和 normal/trade/callback 频道。因此同一台机器上多个 QMT 可以共用一个 PipeHub，但必须通过不同 `bridge_id` 注册到不同频道。未填写 QMT 目录时，系统无法自动复制核心包和写入身份文件，需要通过 `CFQUANT_BRIDGE_ID` 环境变量或手工配置文件区分。

首页账号下拉框显示已保存的账号。切换账号后，资产、持仓、委托、成交、下单、撤单、行情订阅和回调过滤都会使用所选账号的绑定关系。

## 4. 高级模式故障回退

账号配置为高级模式时，请求按以下顺序执行：

1. 优先调用 LTtx；
2. LTtx、普通 QMT 桥或极速交易桥失败时，切换到 ctypes；
3. 返回结果记录 `preferred_mode`、`effective_mode`、`fallback` 和 `fallback_reason`；
4. 高级模式恢复后，下一次请求再次优先尝试 LTtx。

网页启动时，只要存在高级账号，服务端会尝试同时准备 LTtx 和 PipeHub；其中一端启动失败不会阻止系统保存配置，状态页会显示实际模式。回退只有在另一个 QMT 已提供可用的通用通道时才可能成功，不应为了回退在同一 QMT、同一资金账号上同时启动两种模式。

## 5. 共享行情数据源

多账号行情默认只维护一个数据源账号，避免同一台机器上重复订阅全推行情和重复接收回调。

在“账号绑定”表单中勾选“作为共享行情数据提供商”即可指定数据源。系统同时只保留一个数据源账号，后保存的设置会覆盖之前的选择。

行情请求未指定账号时，服务端按以下顺序选择数据源：

1. 当前配置的数据源账号；
2. 默认账号；
3. 其他已启用账号。

数据源账号请求失败时，服务端会尝试下一个已启用账号，并在结果中返回 `data_provider`、`provider_fallback` 和 `provider_attempts`。账号级行情或交易请求仍然严格使用请求账号，不会因为共享行情源而串用交易账号。

## 6. 网页状态含义

绑定状态表显示：

- `首选模式`：账号保存的配置；
- `实际模式`：本次状态探测和请求当前可用的模式；
- `（已回退）`：首选高级模式不可用，当前已经切换到 ctypes；
- `数据源`：该账号是否是共享行情数据提供商；
- `验证`：强制查询该账号的资金和持仓，用于确认绑定关系。

通用模式和极致模式首页只显示一个通用端状态，不再拆分显示“通用查询通道”和“通用交易通道”。高级账号选中后，首页会显示 LTtx、普通 QMT 和极速交易端状态。

## 7. 配置保存位置

账号运行配置由 Web 服务保存到 `runtime/config/cfquant_web_config.json`，字段包括：

- `initialized`
- `account_configs`
- `data_provider_account_id`
- `account_pairs`

其中 `account_configs[account_id]` 保存账号对应的 `qmt_dir`、`bridge_id`、`mode`、`data_provider` 和 `enabled`。不要手工删除正在运行的配置文件；需要重新配置时，优先使用网页中的“重新初始化”。

`bridge_id` 是兼容旧接口和多 QMT 路由的内部字段。普通用户在网页里只需要添加账号配置；外部程序也优先传 `account_id`，让服务端按配置自动路由。
