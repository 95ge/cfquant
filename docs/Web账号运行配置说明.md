# Web 账号运行配置说明

CFQuant 当前只支持极致模式。用户下载并安装 QMT 后，无需预先登录；在 Web 前端完成绑定并保存，系统会自动安装 QMT Python 运行环境、启动 QMT、部署自包含桥接入口并检测通道。

## 1. 初始化

启动 `cfquant run`，访问 `http://127.0.0.1:8765/`。首次访问按初始化向导配置默认资金账号、账户类型和 QMT 目录。网页登录管理是 Web 服务自身的可选认证，与 QMT 启动和账户绑定分开。

初始化只创建 Web 运行配置，不会清空已有项目文件。源码运行默认使用项目目录下的 `runtime/` 和 `log/`；打包版默认使用 Windows `%LOCALAPPDATA%\cfquant\`。可用 `CFQUANT_HOME` 或 `CFQUANT_RUNTIME_DIR` 指定运行数据目录。

## 2. 绑定字段

| 字段 | 说明 |
|---|---|
| 资金账号 | 券商资金账号，按字符串保存，保留前导零 |
| 账户类型 | `STOCK`、`CREDIT`、`FUTURE`、`FUTURE_OPTION` 或 `STOCK_OPTION` |
| QMT 目录 | QMT 安装目录、`bin.x64` 或相邻 `python` 目录；保存时系统解析并校验实际核心目录 |
| 运行方式 | 默认极致模式；高级模式支持 ctypes（默认）或 socket，需要两个不同的 QMT 目录 |
| 模拟／实盘 | 对应托管策略运行环境；不会改变券商账户权限 |
| 同账号独立市场 | 只有上海、深圳分别使用不同 QMT 目录时才开启 |

多 QMT 或多券商时，为每个实际 QMT 目录建立独立绑定。系统自动生成 `account_key` 和 `bridge_id`，外部策略优先传资金账号和账户类型，不要手工猜测内部通道。

## 3. 保存绑定后的自动流程

保存绑定后，Web 服务会依次：

1. 检查 QMT 目录和权限。
2. 安装或更新 QMT Python 运行环境。
3. 生成账户身份和桥接配置。
4. 部署 `CFQUANT_LITE.py` 自包含入口及必要的 SH/SZ 入口。
5. 启动绑定目录中的 QMT。
6. 等待入口策略、查询通道、交易通道和回调通道上线。

用户不需要预先登录 QMT、手动导入策略、创建 QMT 模型或在 QMT 中再次运行入口。若目标 QMT 正在运行，系统会提示正常退出以完成部署；不会强制结束其他进程。重新保存绑定或执行“检测连接”可重试失败任务。

页面中的“导入包和模型已准备”只表示部署文件完成；必须继续等待“托管策略已运行”和通道在线，才能开始接口测试。

## 4. 运行目录和状态

每个终端和资金账号使用独立的托管目录 `QMT安装目录/cfquant_managed/`。部署任务保存在 `runtime/config/qmt_strategy_jobs.json`，Web 重启后会继续处理。QMT 入口使用内嵌的 `EMBEDDED_RUNTIME_CONFIG` 注入账号和通道配置，不要求用户编辑入口源码。

配置写入、策略部署和实际在线是不同状态。以绑定页部署进度、QMT 进程状态和连接检测结果为准。

## 5. 账号与通道

同一 QMT 可绑定多个不同资金账号；Web 按 `account_key`、`bridge_id`、账户类型和资金账号路由请求。`session_id` 只是 MiniQMT 兼容参数，不是 CFQuant 的主路由键。

极致模式使用自包含入口和 PipeHub 通道。外部 Python 默认使用 `CFQUANT_TRANSPORT=auto`，从 Web 运行注册中发现可用通道。除非排查特殊问题，不要手动固定 PipeHub 或 LTtx 参数。

## 6. Web 认证密码

Web 登录认证是控制台自身的可选保护。登录后可在“设置”→“Web 访问”→“网页登录”重置密码；密码文件只用于本机重置，使用后应删除。Web 认证密码与券商账户密码、QMT 启动流程和 `account_key` 相互独立。

## 7. 更新与排查

项目更新会保留配置、数据库和日志；更新入口前会处理绑定的托管 QMT，完成后重新启动。常见检查顺序：

1. 确认 QMT 已安装且绑定目录指向 `bin.x64` 或有效安装目录。
2. 查看 `log\startup\cfquant_startup.log` 的环境安装结果。
3. 在绑定页重新保存配置，等待极致模式入口部署完成。
4. 使用“检测连接”确认查询、交易和回调通道在线。
5. 再执行行情、资金、持仓和委托测试。

旧版通用模式与手工入口导入流程不用于新绑定。双 QMT 的分工、通信类型和配置步骤见[高级模式部署指南](高级模式部署指南.md)。
