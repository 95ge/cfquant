# 官网远程管理

本功能让个人官网账号管理多套 CFQuant。第一版提供状态查看、持仓/当日委托/成交查询、订单记录详情、CFQuant 启停和绑定 QMT 重启。默认关闭，查询和控制分别授权。

## 接入一套部署

1. 更新官网后端与前端到包含本功能的版本，再更新本地 CFQuant。仅更新本地安装包不会自动升级官网。
2. 使用个人账号登录官网，打开 **个人中心 → 管理我的 CFQuant 部署 → 添加部署**。公共共享账号不能接入。
3. 在官网填写项目名称、备注并设置远程权限，创建项目后复制 **项目 API Key**。之后可在“项目设置 → 查看 Key”随时显示、隐藏和复制。
4. 回到本地控制台 **设置 → 官网远程管理**，勾选启用并粘贴该 Key；按需勾选账户查询、CFQuant 启停、QMT 重启，保存。
5. 等待显示“已连接官网”，返回官网查看项目状态。

每套部署使用独立的 Key；同一 Key 不支持多个设备同时接入。项目名称与备注统一在官网配置，本地同步显示，不影响部署身份。

本地仅支持官网预先创建的项目 API Key，不提供官网账号密码登录，也不会自动创建官网项目。Key 验证成功后由本地代理加密保存，后续启动及调整权限可复用已保存的 Key。

项目 Key、官网用户登录凭据、本地交易 API Key、SDK 管理 Token 是不同凭据。官网项目 Key 只允许代理上报状态、领取本项目任务和回传结果，不能读取其他项目或主动发起控制。

## 权限与状态

远程操作需要官网和本地同时授权。官网修改权限不会替用户打开本地开关；本地关闭接入后，代理停止连接。运行状态监控随接入启用，三个操作权限均可关闭。

| 显示项 | 含义 |
| --- | --- |
| 代理在线 | 官网近期收到代理通信；不代表业务或 QMT 可用 |
| CFQuant 运行中 | 当前业务服务已完成启动，并且身份匹配 |
| CFQuant 已停止 | 代理记录了停止意图，且业务接口不可达 |
| CFQuant 不可达 | 接口连接失败，不能认定为正常停止 |
| QMT 进程 / 登录 / 交易桥接 | 分别展示，不以进程存在替代登录成功或查询成功 |
| 代理离线 | 60 秒内未收到通信；状态仅作历史参考，控制按钮禁用 |

没有可靠进程或登录证据时显示“未确认”。手动启动的 QMT 可能无法提供自动登录记录，应结合桥接状态和实际查询判断。账号显示脱敏标识，绑定 ID 使用与本地账号 Key 分离的标识。

## 查询与控制

- 在绑定账号下查询持仓、委托或成交，任务完成后自动显示结果，也可从任务记录打开。每页最多 100 条，网页使用 50 条，支持翻页及记录详情。委托详情包括委托状态、成交数量、成交价格和错误说明等可用业务字段。
- 查询触发实际账户查询；失败、陈旧缓存或部分市场失败会返回失败，不把缺失数据当作完整成功。每次翻页是新的实时查询，行情和成交变化时各页可能不同。
- **停止 CFQuant**：停止本部署业务 Web 服务与核实归属的 LTtx/PipeHub，保留 QMT 和远程代理。代理在线时可再次远程启动。
- **重启 CFQuant**：等待旧进程退出，再按当前部署保存的 Python、工作目录、端口及环境启动，等待新的启动标识就绪。保留 QMT，不重新部署策略入口。
- **重启 QMT**：操作绑定目录对应的 QMT，先展示同目录受影响的绑定；等待登录成功或明确失败。启动更新导致按钮灰色时，沿用本地自动登录等待与重试逻辑。需预先完成该绑定的本地自动启动/登录配置。
- 控制操作要求输入项目名称确认。检测到跨部署共用资源、旧进程身份变化、更新进行中或配置变化时，拒绝执行，需先在本地解决。

每套部署同时执行一个任务。官网不会为离线项目排队积压启停命令。排队任务 60 秒过期；执行中的 QMT 登录可以持续等待，并上报进度。代理超过 120 秒失联时，执行中的任务显示“结果待核对”，恢复连接不会自动重复执行。

操作状态包括等待执行、运行中、成功、失败、已过期、已取消、结果待核对。遇到“结果待核对”，先检查当前状态，再明确发起新的任务；浏览器对网络错误的请求重试复用原请求 ID。

## Key 管理与恢复

在部署详情的“项目设置”中可轮换 Key、撤销接入或删除项目。轮换后旧 Key 立即失效，需在原部署填写新 Key。撤销不会自动停止本地交易服务。已发起的本地操作可能继续完成，此时官网会提示结果待核对。

官网创建项目后如未保存完整 Key，可在该项目的“项目设置 → 查看 Key”重新显示和复制，再填入本地。首次本地接入缺少 Key 会提示 `api_key_required`；更换 Key 验证失败会保留此前的接入配置。旧账号密码接入接口已停用，返回 HTTP 410 与 `api_key_required`。

Key 与设备身份绑定。复制部署目录到另一台电脑时，应创建新的官网项目，并在目标 Windows 用户下重新接入。现有部署的凭据无法在其他 Windows 用户或不同配置路径下直接解密。

## 在自己的 Python 项目中配置

先在官网创建项目和 Key，服务启动后通过已有 `RuntimeManager` 实例接入；下例使用隐藏输入读取 Key：

```python
from getpass import getpass
from cfquant.management import RuntimeManager

runtime = RuntimeManager(home=r"D:\MyApp\cfquant", port=8877,
                         lttx_port=2149, pipe_name=r"\\.\pipe\myapp_cfquant")
# 按现有 SDK 流程初始化并启动 runtime 后：
runtime.remote.configure(
    api_key=getpass("官网项目 API Key："),
    permissions={"queries": True, "service_control": True, "qmt_control": False},
)
print(runtime.remote.status())  # 仅返回状态、项目元信息和 Key 前缀

# 之后调整本地授权，复用已保存的 Key。
runtime.remote.configure(permissions={"queries": True, "service_control": False,
                                      "qmt_control": False})
# 停用远程接入：
runtime.remote.configure(enabled=False)
```

SDK 接入参数为 `enabled`、`api_key`、`permissions`，不接受官网账号、密码、项目名称或备注；名称和备注在官网管理。项目应用自己的配置文件可以保存“是否启用”；完整 Key 不应写入业务配置或日志。

## 运行与部署说明

本地代理是独立的 `python -m cfquant.remote_management --config <web 配置路径>` 进程，由启用后的本地服务自动拉起。它每约 5 秒上报并轮询任务；网络失败时退避重连，最长间隔约 31 秒。通过操作系统文件锁确保每份配置只存在一个有效代理。

代理主动通过 HTTPS 连接官网，无需把本地端口暴露到公网。本地代理调用使用独立 Token，接口限定回环地址；不透传任意 URL、Shell 命令或交易写入请求。官网地址默认 `https://cfquant.org`；管理员可用 `CFQUANT_REMOTE_SITE_URL` 指定 HTTPS 私有环境，HTTP 仅允许本机测试地址。

本地使用当前 Windows 用户的 DPAPI 加密凭据、启动参数及任务结果。文件位于 Web 配置旁，以 `<配置文件名>.remote_management` 为前缀；不要打包这些文件或提交版本库。任务日志保留 90 天并在后续写入时清理。

官网启动时自动新增 `rm_instances`、`rm_keys`、`rm_tasks`、`rm_audit`、`rm_rate` 表，并为旧版 `rm_keys` 自动补充 `encrypted` 字段，不改动既有用户数据。Key 保存校验摘要、前缀与 Fernet 加密副本；完整 Key 仅在创建、轮换和项目所有者主动查看时返回，普通列表不返回，查看操作会记录审计。弹窗默认隐藏 Key，关闭时清空，不写入浏览器存储。

旧版 Key 仅有哈希，无法恢复原文，但可以继续正常接入。需要查看时，请在官网轮换一次并更新本地 Key，之后即可反复查看。撤销或删除会清除对应的加密副本。

官网依赖 `cryptography`（见 `official_site/backend/requirements.txt`）。首次创建或轮换时，服务在数据库旁生成独立的 `<数据库文件主名>.remote-key` 加密主密钥，例如 `data/cfquant_site.remote-key`，Linux 文件权限为 `0600`。备份和迁移必须同时保留数据库与此文件，不要提交 Git 或放入公开下载。主密钥丢失时不会覆盖已有凭据，查看返回 `key_storage_unavailable`；恢复原密钥文件后可继续查看，现有 Key 的哈希校验接入不受影响。

交易查询结果最多对外提供 5 分钟，后续管理请求会清理过期结果；任务与审计保留 90 天。远程 API 响应使用 `private, no-store`，应确保反向代理也不缓存这些接口。

官网发布需要同时包含 `backend/server.py`、`backend/remote_management.py`、`frontend/app.js` 和 `frontend/remote.html`、`remote.js`、`remote.css`。主项目安装包不携带官网服务，官网源码按现有独立发布流程处理。上线前备份官网数据库，并在验证环境使用个人测试账号完成接入与撤销检查。

第一版支持当前 Windows/QMT 用户会话。电脑关机或远程代理退出后，官网无法唤醒机器；需要本地常规启动流程再次拉起服务/代理。没有新增 Windows 开机计划任务、无人值守桌面登录或业务崩溃自动拉起策略。尚不包含 APP、批量管理、自定义策略进程、远程下单/撤单。

## 接口约定

官网接口前缀为 `/api/remote/v1`，为后续 APP 保留独立 API；APP 用户登录授权另行接入。用户接口使用现有官网个人登录会话，代理接口使用 `X-CFQuant-Remote-Key`。

| 方法与路径 | 用途 |
| --- | --- |
| `GET /instances` / `POST /instances` | 使用官网个人登录会话列出 / 创建自己的部署，创建需 `enrollment_id` |
| `POST /instances/{id}` | 修改名称、备注、权限；需要当前 `revision` |
| `POST /instances/{id}/key` | 项目所有者查看当前 Key；需官网个人登录会话，旧版不可恢复 Key 返回 `key_not_recoverable` |
| `POST /instances/{id}/rotate`、`/revoke` | 轮换 / 撤销 Key |
| `DELETE /instances/{id}` | 移除项目并撤销接入 |
| `GET /instances/{id}/tasks` / `POST /instances/{id}/tasks` | 查询 / 提交任务；提交带 `idempotency_key`，控制带 `confirm={id}` |
| `GET /instances/{id}/audit` | 自己项目的操作记录 |
| `POST /agent/validate`、`/agent/register` | 验证 Key / 建立设备连接 |
| `POST /agent/heartbeat`、`/agent/poll` | 状态上报 / 领取任务 |
| `POST /agent/tasks/{id}/begin`、`/result` | 执行前确认 / 回传进度与结果 |

任务白名单：`positions`、`orders`、`trades`、`start_cfquant`、`stop_cfquant`、`restart_cfquant`、`restart_qmt`。QMT 重启还需提交当前 `binding_revision` 和 `affected_bindings`。

本地接入接口为 `GET/POST /api/remote-management`，沿用本地控制台或 SDK 管理鉴权。`/api/remote-agent/*` 是代理专用接口，不接受交易 Key 或官网 Key 替代本地代理 Token。

验证使用隔离数据库、模拟 QMT 和临时进程服务覆盖接口、真实 HTTP、进程生命周期及桌面/手机浏览器流程；公网部署验证使用临时账号和模拟代理。真实券商 QMT 的重启登录效果需在部署环境验收。
